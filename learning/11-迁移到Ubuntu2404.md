# 11 · 迁移到 Ubuntu 24.04（Jazzy）实操

这是"在 24.04 上不用容器、直接把项目跑起来"的步骤。
**每一步都给命令，照着敲就行。** 想理解为什么这么做，看 [10-环境搭建.md](10-环境搭建.md) 第 13 节。

## 先看清：一共只动四样东西

| 要动的 | 从 | 到 |
|---|---|---|
| ① ROS2 版本 | Humble（22.04 专属） | **Jazzy**（24.04 专属） |
| ② 4 个脚本里写死的路径 | `/opt/ros/humble/setup.bash` | `/opt/ros/jazzy/setup.bash` |
| ③ Python 环境 | 3.10 | **3.12**（Jazzy 只认系统自带的 3.12） |
| ④ 重新编译 | — | `Lidar_ws` 必须在新环境下 `colcon build` |

**算法代码一行都不用改。** 改的全是"环境和路径"。

相机 MVS 你已确认 24.04 能跑，这块直接跳过。

---

## 步骤 0：先备份（10 秒，别省）

```bash
cd EGA_Radar_Algorithm
git status                    # 确认工作区干净
git checkout -b ubuntu2404-jazzy
```

保留 `main` 分支原样。改坏了随时 `git checkout main` 回来。

## 步骤 1：装 ROS2 Jazzy

```bash
# 按 ROS2 官方文档配好 noble 的 apt 源（ros2-apt-source 包）
sudo apt update
sudo apt install -y ros-jazzy-desktop python3-colcon-common-extensions

source /opt/ros/jazzy/setup.bash
echo "ROS_DISTRO=$ROS_DISTRO"     # 期望: jazzy
```

再装项目要用的额外依赖（注意包名全部从 `humble` 换成 `jazzy`）：

```bash
sudo apt install -y \
    ros-jazzy-pcl-ros ros-jazzy-pcl-conversions ros-jazzy-pcl-msgs \
    ros-jazzy-tf2-sensor-msgs ros-jazzy-rclcpp-components \
    ros-jazzy-ament-index-cpp ros-jazzy-ament-index-python \
    ros-jazzy-rmw-cyclonedds-cpp

sudo apt install -y libpcl-dev libeigen3-dev libomp-dev \
    libgl1 libglib2.0-0 libxkbcommon-x11-0 libxcb-xinerama0 \
    libxcb-cursor0 libgomp1
```

验证：

```bash
ros2 pkg prefix rclcpp          # 能打印路径就 OK
```

## 步骤 2：装 ndt_omp

`localization` 编译时必须有它，否则 `find_package(ndt_omp)` 直接失败。

> **注意：网上流传的 `autowarefoundation/ndt_omp` 这个地址并不存在。**
> 原始仓库是 [`koide3/ndt_omp`](https://github.com/koide3/ndt_omp)，但它**只有 ROS1 版本**，ROS2 用不了。
> 完整说明见 [10-环境搭建.md](10-环境搭建.md) 3.3 节。

**先试 apt：**

```bash
apt-cache policy ros-jazzy-ndt-omp
```

有候选版本就直接装：

```bash
sudo apt install -y ros-jazzy-ndt-omp
ros2 pkg prefix ndt_omp           # 能打印路径就 OK
```

**apt 里没有的话，用 pclomp + 改两行 CMake：**

```bash
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
git clone https://github.com/dfki-ric/pclomp.git
cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select pclomp
source install/setup.bash

# 验证（pclomp 不是 ROS 包，ros2 pkg prefix 会报 Package not found，属正常）
find ~/ros2_ws/install/pclomp -name "pclomp-config.cmake"
```

然后改 `Lidar_ws/src/localization/CMakeLists.txt` 两行：

```bash
cd EGA_Radar_Algorithm/Lidar_ws/src/localization
sed -i 's|find_package(ndt_omp REQUIRED)|find_package(pclomp REQUIRED)|' CMakeLists.txt
sed -i 's|ndt_omp::ndt_omp|pclomp::registration|' CMakeLists.txt
grep -n "pclomp" CMakeLists.txt   # 确认两处都改到了
```

头文件路径（`pclomp/ndt_omp.h`）和命名空间（`pclomp::`）与原来完全一致，**不用改 include**。

但有一处几乎必然要改：pclomp 上游把 setter 拼错成了 `setOulierRatio`（少一个 t），而项目调用的是 `setOutlierRatio`。编译时如果报

```text
has no member named ‘setOutlierRatio’; did you mean ‘getOutlierRatio’?
```

就执行：

```bash
cd EGA_Radar_Algorithm/Lidar_ws/src/localization/src
sed -i 's|setOutlierRatio(|setOulierRatio(|' localization.cpp
grep -n "OulierRatio" localization.cpp      # 应该输出 1 行
```

## 步骤 3：装 Livox 驱动

**注意：即使你只跑回放、不接雷达，也必须装。** 因为 `lidar_pipeline.launch.py` 在判断"要不要启动雷达"之前，就已经去找这个包了，找不到就直接报错退出。

```bash
# SDK2
git clone https://github.com/Livox-SDK/Livox-SDK2.git
cd Livox-SDK2 && mkdir build && cd build
cmake .. && make -j$(nproc) && sudo make install

# 驱动
mkdir -p ~/livox_ws/src && cd ~/livox_ws/src
git clone https://github.com/Livox-SDK/livox_ros_driver2.git
cd livox_ros_driver2

# 先按 jazzy 编
./build.sh jazzy || ./build.sh humble     # 后者兜底：build.sh 的参数主要用来选 launch 拷贝，不涉及版本 API
```

如果两种参数都编不过，去仓库 issue 里找支持 Jazzy 的 fork（社区改过的基本都能直接用）。

**编完之后还要补一个文件。** 新版驱动的 `launch_ROS2/` 里**没有** `pcd_HAP_launch.py`（只有 `msg_*` 和 `rviz_*`），而项目配置要它。自己生成一个即可：

```bash
SRC=~/livox_ws/src/livox_ros_driver2/launch_ROS2
DST=~/livox_ws/install/livox_ros_driver2/share/livox_ros_driver2/launch_ROS2

sed -E 's/^(xfer_format[[:space:]]*=[[:space:]]*)1/\10/' $SRC/msg_HAP_launch.py > $SRC/pcd_HAP_launch.py
cp $SRC/pcd_HAP_launch.py $DST/
grep -n xfer_format $SRC/pcd_HAP_launch.py     # 应为 = 0（发 PointCloud2）
```

验证：

```bash
source ~/livox_ws/install/setup.bash
ros2 pkg prefix livox_ros_driver2
```

## 步骤 4：重建 Python 环境（3.10 → 3.12）

**环境名保持不变，还叫 `cud128`**，这样 `tools/synchronized_replay.py` 里写死的 `conda activate cud128` 就不用改。

```bash
conda deactivate
conda env remove -n cud128          # 旧的 3.10 环境删掉
conda create -n cud128 python=3.12 -y
conda activate cud128
```

装包：

```bash
cd EGA_Radar_Algorithm
pip install -r requirements.txt

# PyTorch 用 3.12 的 wheel（cu128 对应 Blackwell）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

# ultralytics 加载 .engine 必需
pip install tensorrt
```

> **机器上已有的 CUDA 不用动。** 系统装的 CUDA 工具包只在编译 `.cu` 源码时才用，而本项目没有任何 `.cu`；PyTorch 的 wheel 自带一份 CUDA 运行时。真正要满足的只有两件事：`nvidia-smi` 里的驱动版本够新（5090 需要 ≥ 570），以及 `tensorrt` 的版本和生成 `.engine` 的那套环境匹配。详见 [10-环境搭建.md](10-环境搭建.md) 2.3 节。

验证（这一步不过，后面都不用试）：

```bash
python -V                                            # 期望 3.12.x
python -c "import torch; print(torch.cuda.is_available())"     # 期望 True
python -c "import tensorrt; print(tensorrt.__version__)"
python -c "import open3d, ultralytics, cv2, scipy, PyQt5, serial, filterpy"
```

> 如果 `import open3d` 报 numpy 相关的错，再补一条 `pip install "numpy<2.0"`。
> `open3d` 在 3.12 上要用 0.19 及以上，`pip` 会自动选对版本。

## 步骤 5：改 4 个脚本里的 ROS 路径

一条命令搞定（在仓库根目录执行）：

```bash
cd EGA_Radar_Algorithm

sed -i 's|/opt/ros/humble/|/opt/ros/jazzy/|g' \
    start_fusion.sh \
    tools/synchronized_replay.py \
    record.sh \
    Main_ws/run_scripts/run_referee_web_injector.sh
```

确认改到了：

```bash
grep -rn "ros/humble" . --include=*.sh --include=*.py
# 应该没有输出
```

**为什么要改这四个**：

- `start_fusion.sh` —— 启动入口，`source` 三次，不改启动即失败。
- `tools/synchronized_replay.py` —— 回放启动器，**它内部拼接 shell 脚本时把路径写死了**，不改回放必失败。
- `record.sh` —— 录制脚本。
- `run_referee_web_injector.sh` —— 裁判网页注入小工具。

## 步骤 6：重新编译

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash        # ndt_omp
cd EGA_Radar_Algorithm/Lidar_ws
colcon build --symlink-install
source install/setup.bash
```

期望结果：`localization`、`dynamic_cloud`、`cluster`、`rm2026_vision_interface`、`rm2026_lidar_launch` 全部 `Finished`。

### 有一个警告可以忽略

`localization` 可能带一条 `stderr output`，内容是关于 `rclcpp/node_impl.hpp` 里 `Node::create_service` 的 `note: declared here`。
这是 Jazzy 对旧版 `create_service` 重载的**弃用警告**：项目里写的是

```cpp
create_service<Trigger>("~/reset_registration", callback, rmw_qos_profile_services_default, callback_group)
```

新版本推荐省略 QoS 参数。**只是警告，编译产物正常，不影响运行**，不用管。

如果哪天要消掉它，把那一行的 `rmw_qos_profile_services_default` 删掉改成四个参数即可。

如果报错，看下面的「编译期可能遇到的问题」。

## 编译期/运行期可能遇到的问题

### 1. `Compatibility with CMake < 3.5 has been removed`

Ubuntu 24.04 自带 CMake 3.28，只会警告；但如果你 `pip install cmake` 装了 4.x，就会直接报错。
**解决**：把 5 个 `CMakeLists.txt` 里的 `cmake_minimum_required(VERSION 3.8)` 改成 `3.16`。

```bash
cd Lidar_ws/src
sed -i 's/VERSION 3.8/VERSION 3.16/' */CMakeLists.txt
```

### 2. `read_points` 返回值变了

`driver/lidar/ros2_lidar_client.py` 里是这样用的：

```python
for x, y, _z in point_cloud2.read_points(msg, field_names=("x","y","z"), skip_nans=True):
```

新版 `sensor_msgs_py` 可能返回 numpy 数组而不是元组。如果启动时报
`ValueError: too many values to unpack` 或类似错误，改成用 `read_points_list`：

```python
for p in point_cloud2.read_points_list(msg, field_names=("x","y","z"), skip_nans=True):
    x, y, _z = p.x, p.y, p.z
```

（先别改，跑起来报错了再改。这是唯一可能需要动 Python 代码的地方。）

### 3. RViz 配置版本不匹配

打开 RViz 会提示配置文件版本较旧，点确认即可。个别显示项（比如自定义点云着色）可能失效，删掉重新加一次就行。

### 4. engine 加载失败

只有在你**换了 CUDA 或 TensorRT 版本**时才会发生。GPU 没换、版本没变的话，原来那两个 `.engine` 直接可用。
真遇到了就重导：

```bash
cd Main_ws && python utils/convert_pt2tensorrt.py
```

（装甲模型那段在脚本里是注释掉的，需要时手动取消注释。）

### 5. 编译报 `ament_target_dependencies` 弃用

只是警告，不影响编译。这个项目实际上没用到这行，可以忽略。

## 改完之后怎么判断"真的没问题"

按这个顺序，四步都过就可以放心用：

```text
1. python -c "import torch; print(torch.cuda.is_available())"   → True
2. 7 秒回放样例能正常显示目标                                    → 通过
3. 完整 9.9 分钟回放，目标位置和 22.04 上的结果基本一致            → 通过
4. UI 里的残差统计（projection_lidar_statistics）均值在 0.2~0.5m  → 标定正常
```

**第 3 步是唯一真正的验收标准**：同一份录像、同一个配置，两个系统跑出来的坐标差值应该在几十厘米以内。差太多说明配准行为变了，需要重新标定。

## 回滚

```bash
cd EGA_Radar_Algorithm
git checkout main                 # 回到改动前
conda activate cud128             # 但注意：环境已经被换成 3.12 了
```

所以**建议不要删旧的 3.10 环境**，改成换个名字建新的：

```bash
conda create -n cud128_jazzy python=3.12 -y       # 新环境用新名字
conda activate cud128_jazzy
# 然后把 tools/synchronized_replay.py 里的 conda activate cud128 改成 cud128_jazzy
```

这样 22.04 和 24.04 两套环境可以并存。
