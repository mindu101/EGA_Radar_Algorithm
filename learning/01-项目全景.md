# 01 · 项目全景

## 这是什么

RoboMaster 2026 赛季 **香港科技大学 ENTERPRIZE 战队**的雷达站算法开源（MIT License）。
雷达站是比赛里一个「不开火、只观测」的角色：它架在场边，用**相机 + 激光雷达**持续估计对方 5 台地面机器人和 1 台空中机器人的位置，通过裁判系统串口把坐标广播给己方。

所以这个项目的本质任务只有一句：

> **在 28m × 15m 的场地上，实时输出 10 个固定身份（B1~B4, B7, R1~R4, R7）的二维坐标，并标注每个坐标是「确认」「猜测」还是「预测」。**

难点在于：雷达能测位置但不知道是谁，相机知道是谁但测不准位置。整套架构都是围绕这个矛盾展开的。

### 开源边界

`OPEN_SOURCE_CONTENTS.md` 里写得很清楚，**不包含**：

- `RM2026_Waves_Analyze/` —— 信息波 / 干扰波的 MATLAB 解析算法（只保留了通信接口，默认关闭）。
- 激光云台自动瞄准项目（含模型、配置、驱动）。

**包含**：ROS2 点云管线、Python 主程序、TensorRT engine 与对应 PT/ONNX、场地 PLY/PCD 地图、全部配置、同步回放工具。

这解释了配置里为什么会出现 `use_info_wave_0a01_for_referee: false`、`enable_info_wave_robot_multicast: false` —— 接口在，实现不在，默认关闭，不影响融合定位主链路。

## 硬件

| 部件 | 型号 | 关键参数 |
|---|---|---|
| 相机 | 海康 MV-CS120-10UC + 6mm 广角 | 4024×3036 @ 30Hz，曝光 10000μs，增益 23 |
| 激光雷达 | Livox HAP | 非重复扫描，ROS2 驱动 `livox_ros_driver2` |
| 算力 | RTX 5090 + Intel Core Ultra 9 275HX 笔记本 | 模型全部走 TensorRT + FP16 |

注意相机是 **4024×3036 的超大分辨率**（约 1220 万像素），这直接影响了两处设计：

- 视觉流水线必须拆成 A/B 两级，否则单帧处理时间撑不住 30Hz（见 [02-架构与数据流.md](02-架构与数据流.md)）。
- UI 叠图必须先在后台缩到 1280×960 再画框，否则主线程复制大图会卡死（`visualization.output_max_width`）。

## 构建与运行

```bash
# 1. 构建 ROS2 侧
source /opt/ros/humble/setup.bash
source ../livox_ws/install/setup.bash
cd Lidar_ws && ./build.sh

# 2. 一键启动（先起 ROS2 管线，再起 Python 主程序）
./start_fusion.sh

# 可选环境变量
CONDA_ENV=cud128 LAUNCH_RVIZ=false LIVOX_WS_DIR=/path/to/livox_ws ./start_fusion.sh
```

`start_fusion.sh` 做了两件事，读完这 55 行你就理解进程关系了：

1. 后台 `ros2 launch rm2026_lidar_launch lidar_pipeline.launch.py`（ROS2 三个节点 + 可选 RViz + Livox 驱动）。
2. 前台 `conda activate` 后进入 `Main_ws`，执行 `python main.py --config config/params.yaml --device_config config/device.yaml`。

**启动后并不是马上开始定位**：`main.py` 会先弹出 Qt 界面，需要人工完成相机外参标定（选场地关键点 → solvePnP）并点「启动雷达站」，`MainEventLoop.run()` 才被调用。
这个「有人在环」的标定步骤是刻意的——雷达站每天都可能换个位置架设。

## 关键数字速查

读代码时这些常量会反复出现，先记住比例关系即可：

| 项 | 值 | 出处 |
|---|---|---|
| 场地尺寸 | 28.0 m × 15.0 m | `params.yaml: lidar_fusion` |
| 身份编码 | 0–4 = B1,B2,B3,B4,B7；5–9 = R1..R7；10–14 = G1..G7 | `armor_detector.class_names` |
| 组合置信度 | `0.70 × 数字置信度 + 0.30 × 装甲置信度` | `digit_detector` 权重 |
| 彩色匹配门限 | 1.5 m | `colored_triplet_match.max_ray_lidar_distance_m` |
| 历史续接门限 | 2.0 m | `history_lidar_match.max_distance_m` |
| 雷达快照有效期 | 0.20 s | `lidar_fusion.max_snapshot_age_sec` |
| 单帧提交最大年龄 | 0.20 s | `detection_pipeline.max_commit_age_sec` |
| 卡尔曼测量噪声 | σ = 0.20 m | `position_kalman.lidar_r_std_m` |
| 位置硬重置阈值 | 2.5 m | `position_kalman.hard_reset_distance_m` |
| 允许纯雷达猜点 | 丢失 ≥ 10 帧 | `loss.radar_guess_after_frames` |

## 三类坐标，别搞混

这是新手读这个仓库最容易翻车的地方。代码里同时存在三套坐标：

1. **`livox_frame`** —— 雷达自身坐标系（`device.yaml` 里的 `lidar.extrinsics`）。
2. **`rm_frame`** —— 场地全局坐标系，单位米，原点在场地一角。ROS2 侧输出的都是这个。
3. **「己方半场视角」坐标** —— Python 融合层为统一红蓝逻辑做的镜像坐标：蓝方运行时把 `x → 28-x`、`y → 15-y`。**这个坐标只存在于 `CascadeMatchTracker` 内部和 UI 里**，发裁判系统前不再镜像。

具体在两个函数里做镜像：`solidwork2uwb()`（视觉投影点）和 `_prepare_frame_inputs()`（雷达点）。
详见 [05-像素到场地坐标.md](05-像素到场地坐标.md)。
