# 10 · 运行环境（完整）

这篇回答"跑起来到底要装什么"。按**层**组织，因为这套系统实际上是三套环境叠在一起的：

```text
┌─────────────────────────────────────────────┐
│  第 3 层：conda Python 环境（cud128）        │  PyTorch / ultralytics / Open3D / PyQt5
├─────────────────────────────────────────────┤
│  第 2 层：ROS2 Humble + 两个工作空间         │  Lidar_ws（本仓库）、livox_ws（雷达驱动）
├─────────────────────────────────────────────┤
│  第 1 层：Ubuntu 22.04 + NVIDIA 驱动 + CUDA  │  TensorRT、PCL、OpenMP、MVS SDK
└─────────────────────────────────────────────┘
```

**任何一层缺失都会报错，而且报错信息分布在三个不同地方**（终端、ROS 日志、Python traceback），所以按层排查最有效。

## 1. 硬件

| 部件 | 官方配置 | 是否可省 | 说明 |
|---|---|---|---|
| 计算平台 | RTX 5090 + Ultra 9 275HX | 不可省（可换同级 NVIDIA 卡） | 模型全部走 TensorRT + FP16 |
| 相机 | 海康 MV-CS120-10UC + 6mm | **回放可省** | 4024×3036@30Hz |
| 激光雷达 | Livox HAP | **回放可省** | 以太网连接，需配网段 |
| 裁判系统串口 | USB 转 TTL，默认 `/dev/referee` | **可省** | 缺失时自动扫描，不影响算法加载 |

项目总大小约 **620 MB**（其中 `weights/` 约 265 MB）。加上 ROS2、CUDA、conda 环境，实际占用 **25–40 GB**。

## 2. 第 1 层：系统

### 2.1 操作系统

**Ubuntu 22.04 LTS（jammy）**，这是 ROS2 Humble 的官方支持版本。
不要用 24.04——Humble 没有 noble 的二进制包，`apt install ros-humble-*` 会直接失败。

### 2.2 NVIDIA 驱动

需要支持 RTX 5090（Blackwell 架构，`sm_120`）的驱动版本。太老的驱动会出现：

```text
NVIDIA-SMI has failed because it couldn't communicate with the NVIDIA driver
```

或 PyTorch 报：

```text
CUDA error: no kernel image is available for execution on the device
```

后者的含义是"编译时的算力目标不包含你的卡"，**不是驱动问题而是 CUDA/torch 版本问题**，见 2.3。

### 2.3 CUDA 与 TensorRT

项目没有钉死版本，但有两处强约束：

**① TensorRT engine 与生成它的环境强绑定。**
`weights/*.engine` 是用官方那台机器导出的；如果你的 TensorRT 主版本不同，加载会失败。README 里明确写了：

> TensorRT engine 与生成它的 GPU 架构、CUDA 和 TensorRT 版本有关。如果目标机器不兼容，应使用同目录下的 PT/ONNX 文件重新转换。

**② 环境名 `cud128` 是一个线索。**
`start_fusion.sh` 里默认 `CONDA_ENV="${CONDA_ENV:-cud128}"`。这个命名强烈暗示官方用的是 **CUDA 12.8**——这与 RTX 5090（Blackwell）需要 CUDA 12.8+ 才能编译出 `sm_120` kernel 的事实一致。

> 标注：CUDA 12.8 / TensorRT 10.x 是**从环境名和硬件推断**的，仓库没有显式声明版本号。以你自己实际能跑通的组合为准。

**如果机器上已经装了 CUDA，不要重装。** 先把三个东西分清楚：

| 命令 | 看的是什么 | 对本项目重要吗 |
|---|---|---|
| `nvidia-smi` 第一行的 `CUDA Version` | **驱动支持的最高版本** | **重要**。这才是 PyTorch / TensorRT 真正依赖的东西 |
| `nvcc --version` | 系统装的 CUDA 工具包 | **几乎不重要**。只在编译 `.cu` 源码时需要，而本项目一个 `.cu` 都没有 |
| `torch.version.cuda` | 当前 torch 用的 CUDA 运行时 | 参考值，由安装的 wheel 决定 |

关键事实：**PyTorch 的 pip wheel 自带 CUDA 运行时和 cuDNN**，不依赖系统工具包。所以：

- 系统装的是 CUDA 12.4，照样可以 `pip install torch --index-url .../cu128`，只要**驱动够新**（5090 需要 ≥ 570）。
- 不需要 `sudo apt install cuda-toolkit-12-8` 让系统工具包与 wheel 对齐。
- 已装的 CUDA 保留即可，不用删、不用升级，不影响本项目任何环节。

真的需要系统 CUDA 工具包的场合只有两种：要自己编译 CUDA 核（本项目没有），或用 `nvcc` 做某些自定义构建（也没有）。

**建议组合**（2026 年的 Blackwell 卡）：

```text
NVIDIA 驱动     ≥ 570
CUDA Toolkit     12.8
TensorRT         10.x（与 CUDA 12.8 匹配）
PyTorch          cu128 wheel（2.7+）
```

### 3.3 ⚠️ `ndt_omp` —— 最容易卡住的一步

`localization` 的 CMakeLists 里有：

```cmake
find_package(ndt_omp REQUIRED)
target_link_libraries(${LOCALIZATION_NODE} ${PCL_LIBRARIES} ndt_omp::ndt_omp)
```

代码里包含的头文件是：

```cpp
#include <pclomp/ndt_omp.h>
```

它要求一个 **CMake 包名为 `ndt_omp`、并导出 `ndt_omp::ndt_omp` 这个 target** 的库，头文件在 `pclomp/` 目录下。

**这一步不像别的包一句 `apt install` 就能过**，原因是这个库的上游有点乱：

| 仓库 | 状态 |
|---|---|
| [`koide3/ndt_omp`](https://github.com/koide3/ndt_omp) | **原始作者，只有 ROS1（catkin）版本**。README 明确写着：ROS2 或无 ROS 项目请用下面两个 fork |
| [`tier4/ndt_omp`](https://github.com/tier4/ndt_omp) | master 分支也是 catkin 版（我核对过 CMakeLists），不能直接用于 ROS2 |
| [`dfki-ric/pclomp`](https://github.com/dfki-ric/pclomp) | **纯 CMake，无 ROS 依赖，ROS2 可用**，头文件同样是 `pclomp/*.h` |
| [`rsasaki0109/ndt_omp_ros2`](https://github.com/rsasaki0109/ndt_omp_ros2) | ROS2 移植版，但**包名叫 `ndt_omp_ros2`**，不是 `ndt_omp` |

所以有两条路：**先试 apt，不行就用 pclomp 并改两行 CMake**。

#### 路线 1：先看 apt 里有没有现成的

```bash
apt-cache search ndt_omp
apt-cache policy ros-jazzy-ndt-omp ros-humble-ndt-omp 2>/dev/null
```

如果 `ros-jazzy-ndt-omp` 有候选版本，直接 `sudo apt install ros-jazzy-ndt-omp`，然后跳到验证。

#### 路线 2：装 pclomp，改两行 CMake（确定可行）

```bash
cd ~/ros2_ws/src
git clone https://github.com/dfki-ric/pclomp.git
cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select pclomp
source install/setup.bash
```

然后改 `Lidar_ws/src/localization/CMakeLists.txt`：

```bash
cd EGA_Radar_Algorithm/Lidar_ws/src/localization

# 第 1 处：包名
sed -i 's|find_package(ndt_omp REQUIRED)|find_package(pclomp REQUIRED)|' CMakeLists.txt

# 第 2 处：链接的 target
sed -i 's|ndt_omp::ndt_omp|pclomp::registration|' CMakeLists.txt

# 确认改到了
grep -n "pclomp" CMakeLists.txt
```

改完这两处，**C++ 代码里的头文件路径和命名空间都不用动**——`#include <pclomp/ndt_omp.h>` 和 `pclomp::NormalDistributionsTransform` 都还是原样。

##### 还可能要多改一行 C++：pclomp 把 setter 拼错了

pclomp 的 `ndt_omp.h` 里有一个上游遗留的拼写错误——setter 写成了 `setOulierRatio`（少了一个 t），而项目代码调用的是正确拼写 `setOutlierRatio`。于是编译报：

```text
... has no member named ‘setOutlierRatio’; did you mean ‘getOutlierRatio’?
```

改一行就好：

```bash
cd EGA_Radar_Algorithm/Lidar_ws/src/localization/src
sed -i 's|setOutlierRatio(|setOulierRatio(|' localization.cpp
grep -n "OulierRatio" localization.cpp      # 应该输出 1 行
```

功能完全一样（设的就是同一个 `outlier_ratio_` 成员），只是名字少个字母。
**如果编译没报这个错，就不用改。**

#### 验证（两条路都要过这一关）

**路线 1（apt 装的 `ndt_omp`）**：它是 ROS 包，可以这样查：

```bash
ros2 pkg prefix ndt_omp
```

**路线 2（pclomp）**：它是**纯 CMake 项目，不是 ROS 包**，所以 `ros2 pkg prefix pclomp` 会报 `Package not found`——**这是正常的，不代表没装好**。要这样验证：

```bash
source ~/ros2_ws/install/setup.bash
find ~/ros2_ws/install/pclomp -name "pclomp-config.cmake"
```

期望输出类似：

```text
/home/xxx/ros2_ws/install/pclomp/lib/cmake/pclomp/pclomp-config.cmake
```

只要这个文件在、并且 source 过 `~/ros2_ws/install/setup.bash`，`find_package(pclomp)` 就能找到。

### 3.4 第 2 层之二：`livox_ros_driver2`

**必须单独建一个工作空间**，默认位置是项目同级的 `../livox_ws/`，或用 `LIVOX_WS_DIR` 覆盖。

安装顺序（Livox 官方要求先装 SDK2，再编译驱动）：

```bash
# 1) Livox SDK2
git clone https://github.com/Livox-SDK/Livox-SDK2.git
cd Livox-SDK2 && mkdir build && cd build
cmake .. && make -j$(nproc) && sudo make install

# 2) livox_ros_driver2
mkdir -p ~/livox_ws/src && cd ~/livox_ws/src
git clone https://github.com/Livox-SDK/livox_ros_driver2.git
cd livox_ros_driver2
# 按你的 ROS2 版本构建（Humble）
./build.sh humble
```

> **⚠️ 一个反直觉的坑：连"只跑回放"也必须装它。**
>
> `lidar_pipeline.launch.py` 在判断 `start_livox` **之前**就已经执行了：
>
> ```python
> livox_pkg_share = get_package_share_directory("livox_ros_driver2")
> livox_launch_path = _resolve_path(livox_launch_file, livox_pkg_share)
> if not os.path.exists(livox_launch_path):
>     raise RuntimeError(f"livox launch file not found: {livox_launch_path}")
> ```
>
> 而回放时传的是 `start_livox:=false`。所以**即使你根本不接雷达，只要没装 `livox_ros_driver2`，launch 一样会抛 `PackageNotFoundError`**。

默认要用的 launch 文件是 `launch_ROS2/pcd_HAP_launch.py`（HAP 型号）。如果你换型号，改 `Lidar_ws/src/rm2026_lidar_launch/config/params.yaml` 的 `lidar_pipeline.livox_launch_file`。

> **⚠️ 第二个坑：新版 Livox 驱动里没有 `pcd_*_launch.py`。**
>
> 项目配置写的是 `launch_ROS2/pcd_HAP_launch.py`，但上游 `launch_ROS2/` 目录里现在只有三类文件：
> `msg_*_launch.py`（xfer_format=1，发 CustomMsg）、`rviz_*_launch.py`、`rviz_mixed.py`。
> **`pcd_*` 系列在老版本里有，新版本被删了**，于是启动时报：
>
> ```text
> Caught exception in launch: livox launch file not found: .../launch_ROS2/pcd_HAP_launch.py
> ```
>
> 解决办法是**自己生成一个**：复制 `msg_HAP_launch.py`，只把 `xfer_format` 从 1 改成 0（0 = 发标准 PointCloud2，正是 `localization` 订阅的 `/livox/lidar` 类型）：
>
> ```bash
> SRC=~/livox_ws/src/livox_ros_driver2/launch_ROS2
> DST=~/livox_ws/install/livox_ros_driver2/share/livox_ros_driver2/launch_ROS2
>
> # 生成 pcd 版（只改 xfer_format 那一行）
> sed -E 's/^(xfer_format[[:space:]]*=[[:space:]]*)1/\10/' $SRC/msg_HAP_launch.py > $SRC/pcd_HAP_launch.py
> grep -n "xfer_format" $SRC/pcd_HAP_launch.py     # 应显示 = 0
>
> # 源码目录和安装目录各放一份（安装目录才会被 launch 找到）
> cp $SRC/pcd_HAP_launch.py $DST/
> ls -l $DST/pcd_HAP_launch.py
> ```
>
> 两个目录都要放：**launch 实际读的是 install 里那份**，但源码那份能保证你以后重新 `./build.sh` 时不会丢。
>
> 注意：这个文件**回放时也必须存在**（launch 在判断 `start_livox` 之前就检查了它），只是回放不会真的启动它。
>
> 别把配置改成指向 `launch/` 目录——那是 `build.sh` 临时创建的副本，编译完就被删了。

### 4.3 `requirements.txt` 里**没有**但必须装的两个

**① TensorRT 的 Python 包**

`weights/*.engine` 是 TensorRT 引擎，ultralytics 加载 `.engine` 时需要 `tensorrt` 模块：

```bash
pip install tensorrt==10.x.x      # 版本必须与本机 TensorRT 运行库一致
```

没装会报：

```text
ModuleNotFoundError: No module named 'tensorrt'
```

**② 与 CUDA 匹配的 PyTorch**

`pip install torch` 默认装 CUDA 版本，但如果驱动/CUDA 是 12.8，建议显式指定 wheel 源：

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

验证：

```bash
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
# 期望输出类似: 2.7.x 12.8 True
```

### 4.4 `ultralytics` 版本要点

仓库的 `config/botsort.yaml` 里有这两个键：

```yaml
with_reid: false
model: auto      # uses native features if detector is YOLO else yolo11n-cls.pt
```

`model: auto` 是较新版本才支持的键。用太老的 ultralytics 会出现"跟踪器配置项未知"或行为不符。
建议用 **8.3.x 或更新**，装完验证：

```bash
python -c "import ultralytics; print(ultralytics.__version__)"
```

### 4.5 关于 `torch` 与 engine 的相互作用

有点反直觉：**TensorRT engine 不依赖 torch**，但 ultralytics 加载 engine 走的是自己的 `AutoBackend`，仍然会 import torch。所以：

- 只跑推理 → torch 必需
- 但 engine 精度/速度不受 torch 版本影响

## 5. 海康 MVS SDK（相机）

### 5.1 安装位置是写死的

`Main_ws/driver/hik_camera/hik.py` 第 12 行：

```python
os.environ["MVCAM_COMMON_RUNENV"] = "/opt/MVS/lib"
```

而 `Main_ws/run_scripts/camera_capture.sh` 里是：

```bash
cd /opt/MVS/bin/ && sh ./MVS.sh
```

**所以 MVS SDK 必须装在 `/opt/MVS`**（海康 Linux 安装包的默认位置）。装到别处需要改这两处。

### 5.2 装什么

从海康机器人官网下载 **MVS Linux 安装包**（x86_64），安装：

```bash
tar -zxvf MVS-x.x.x_x86_64_xxxxxxxx.tar.gz
cd MVS-x.x.x_x86_64_xxxxxxxx
sudo ./install.sh
```

验证运行库：

```bash
ls /opt/MVS/lib/libMvCameraControl.so
```

仓库自带的是 **Python 封装**（`MvImport/` 六个文件），厂商运行库不随仓库提供——这就是为什么必须单独装 MVS。

### 5.3 权限

相机走 USB3，普通用户需要 udev 规则才能免 sudo：

```bash
# 海康安装脚本通常已处理；若报权限错误：
sudo usermod -aG plugdev $USER
# 重新登录生效
```

## 6. 裁判系统串口（可选）

默认设备 `/dev/referee`。没有这个设备时：

- `RefereeCommManager` 会自动扫描非 Pluto 的 USB 串口并重试；
- 完全不影响算法加载和雷达融合。

想固定成 `/dev/referee`，加一条 udev 规则（`idVendor`/`idProduct` 用 `lsusb` 查）：

```bash
# /etc/udev/rules.d/99-referee.rules
SUBSYSTEM=="tty", ATTRS{idVendor}=="xxxx", ATTRS{idProduct}=="xxxx", SYMLINK+="referee", MODE="0666"
```

```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
```

没有裁判系统时，阵营（红/蓝）只能靠 `test.yaml` 的 `runtime.faction` 或 UI 手动指定。

## 7. 模型与 TensorRT engine

### 7.1 仓库自带什么

| 文件 | 大小 | 用途 |
|---|---|---|
| `weights/car/best.engine` | 23 MB | 车辆检测（TensorRT） |
| `weights/car/best.pt` / `.onnx` | 19 / 37 MB | 重新导出用 |
| `weights/armor/armor_best.engine` | 43 MB | 装甲检测（TensorRT） |
| `weights/armor/armor_best.pt` / `.onnx` | 39 / 77 MB | 重新导出用 |
| `weights/MobileNetv2.2.pth` | 26 MB | 数字分类（PyTorch，**不是** engine，不需要重导） |

### 7.2 engine 不兼容怎么办

症状：启动时抛 TensorRT 相关异常，或输出全是乱码框。

```bash
cd Main_ws
python utils/convert_pt2tensorrt.py
```

脚本里两个模型的导出参数（**不要随意改**，改了要和推理侧对齐）：

| 模型 | imgsz | half | batch | dynamic |
|---|---|---|---|---|
| 车辆 `best.pt` | 1280 | True | 1 | False |
| 装甲 `armor_best.pt` | 192 | True | 10 | True |

注意装甲模型那段在脚本里是**被注释掉的**，要用时手动取消注释（或者改一行 `model = YOLO(...armor...)`）。

> 为什么装甲是 `batch=10, dynamic=True`：B 阶段要把**所有车辆 ROI 一次批量推理**，车辆数不固定，所以需要动态 batch。

## 8. 完整构建流程

把上面所有东西串起来，从零到能跑：

```bash

sudo apt update && sudo apt install -y build-essential cmake git \
    libpcl-dev libeigen3-dev libomp-dev \
    libgl1 libglib2.0-0 libxkbcommon-x11-0 libxcb-xinerama0 libxcb-cursor0 libgomp1

    ros-humble-tf2-sensor-msgs ros-humble-rclcpp-components
source /opt/ros/humble/setup.bash

# ---------- 2. ndt_omp ----------
# 先试 apt：有就直接装
apt-cache policy ros-humble-ndt-omp
# 没有的话用 pclomp（并改 localization/CMakeLists.txt 两行，见 3.3 节）
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
git clone https://github.com/dfki-ric/pclomp.git
cd ~/ros2_ws && colcon build --packages-select pclomp
source install/setup.bash
ros2 pkg prefix pclomp           # 注意：pclomp 不是 ROS 包，这条会报 Package not found，属正常
find ~/ros2_ws/install/pclomp -name "pclomp-config.cmake"    # 用这条验证

# ---------- 3. Livox SDK2 + driver ----------
git clone https://github.com/Livox-SDK/Livox-SDK2.git
cd Livox-SDK2 && mkdir build && cd build && cmake .. && make -j$(nproc) && sudo make install
mkdir -p ~/livox_ws/src && cd ~/livox_ws/src
git clone https://github.com/Livox-SDK/livox_ros_driver2.git
cd livox_ros_driver2 && ./build.sh humble
source ~/livox_ws/install/setup.bash

# ---------- 4. 海康 MVS ----------
cd /path/to/MVS-installer && sudo ./install.sh
ls /opt/MVS/lib/libMvCameraControl.so

# ---------- 5. Python ----------
conda create -n cud128 python=3.10 -y && conda activate cud128
cd EGA_Radar_Algorithm
pip install -r requirements.txt
pip install "numpy<2.0"
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install tensorrt                # 版本与系统 TensorRT 一致
python -c "import torch, ultralytics, open3d; print(torch.cuda.is_available())"

# ---------- 6. 构建本仓库的 ROS2 工作空间 ----------
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash          # ndt_omp
cd EGA_Radar_Algorithm/Lidar_ws
./build.sh                                    # 就是 colcon build --symlink-install
source install/setup.bash
ros2 pkg list | grep -E "localization|dynamic_cloud|cluster|rm2026"
```

## 11. 常见环境错误对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `PackageNotFoundError: "ndt_omp"` | ndt_omp 没装或没 source | 见 3.3 |
| `Could not find a package configuration file provided by "ndt_omp"` | 同上（编译期） | 先 source ndt_omp 的 install |
| `PackageNotFoundError: "livox_ros_driver2"` | 没装 Livox 驱动（**回放也会报**） | 见 3.4 |
| `ModuleNotFoundError: No module named 'tensorrt'` | 缺 TensorRT Python 包 | `pip install tensorrt` |
| `ModuleNotFoundError: No module named 'matplotlib'` | 缺包（`ray_renderer` 顶层导入） | `pip install matplotlib` |
| `libGL.so.1: cannot open shared object file` | 缺图形库（Open3D / PyQt5） | `sudo apt install libgl1` |
| `Could not load the Qt platform plugin "xcb"` | 缺 xcb 库或跑在纯 Wayland | 装 2.4 的 xcb 包；改用 X11 会话 |
| `CUDA error: no kernel image is available` | torch 的 CUDA 版本不含你的算力 | 换 cu128 版 torch |
| engine 加载失败 / 输出乱码 | TensorRT 版本不匹配 | 用 `.pt` 重新导出，见 7.2 |
| `Unable to open /dev/referee` | 没有裁判串口 | 无害；或用 `disable_referee_io` |
| 相机初始化超时 | MVS 没装 / 权限 / 相机被占用 | 见第 5 节 |
| `/livox/lidar` 没有数据 | 网段没配对 / 驱动没起 | `ping` 雷达 + `ros2 topic hz` |
| `ros2 launch` 找不到 launch 文件 | 改了源码没重新 `colcon build` | 见下 |

### 最后一个容易踩的：源码配置与安装副本

`build.sh` 执行的是 `colcon build --symlink-install`。符号链接不等于"所有文件都实时跟随源码"，而**回放和正式运行读的根本不是同一份配置**（`replay_README.md` 7.6 节明说了这件事）：

```text
回放：读源码   Lidar_ws/src/rm2026_lidar_launch/config/params.yaml
实机：读安装副本 Lidar_ws/install/rm2026_lidar_launch/share/rm2026_lidar_launch/config/params.yaml
```

于是会出现这种迷惑现象：**回放一切正常，实机行为却不同**。

**结论：改完雷达侧任何配置或 C++，一律 `cd Lidar_ws && ./build.sh`，然后对比 src 与 install 两份 yaml 是否一致。**

## 13. 能不能用 Ubuntu 24.04？

能，但**不是"改两行"级别的事**。前提事实：ROS2 Humble 的官方二进制包只发布给 jammy（22.04），24.04（noble）对应的发行版是 **Jazzy**。所以只有三条路，代价差别很大。

### 路线 A：用 22.04 容器（推荐）

系统保持 24.04，用 Docker / distrobox 跑一个 22.04 镜像。**代码零改动**，这是唯一不需要验证算法行为的方案。

```dockerfile
FROM ubuntu:22.04
# 安装 ROS2 Humble + PCL + ndt_omp + Livox SDK2 + livox_ros_driver2
# NVIDIA Container Toolkit 透传显卡
```

再挂载 X11（Qt 和 RViz 需要）：

```bash
docker run --gpus all -e DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix ...
```

实机运行要注意：**相机和雷达要透传给容器**（`--device` 或 `--privileged`），MVS SDK 装在镜像里的 `/opt/MVS`。

### 路线 B：换 ROS2 Jazzy（改代码）

C++ 侧其实改动不大——`rclcpp`、`tf2_ros`、`pcl_conversions`、`std_srvs`、`rclcpp_components` 这些 API 在 Humble→Jazzy 之间基本兼容，`rclcpp_components_register_node`、`ament_auto_add_library` 都还在。`ndt_omp` 和 `livox_ros_driver2` 也都有 Jazzy 版本。

**真正的连锁反应在 Python 侧，而且这个链条很容易被忽略：**

```text
Ubuntu 24.04 + ROS2 Jazzy
        ↓  rclpy 是针对系统 Python 3.12 编译的
main.py 顶层就有 import rclpy
        ↓  所以整个 Python 进程必须是 3.12
conda 环境必须建 python=3.12（不能再用 3.10）
        ↓  连带要求
open3d 需要 0.19+（0.18 的 wheel 只到 3.11）
torch 要 cp312 的 cu128 wheel
```

也就是说：**"用 24.04" 会自动把整套 Python 依赖升级一个大版本**，这比改 ROS 发行版风险更大。好消息是仓库自己的代码里没有 `distutils`、`pkg_resources`、`np.float` 这类 3.12 已删除/弃用的东西（我扫过一遍，`Main_ws` 里除 `pfa_yolov5` 副本外是干净的）。

### 路线 C：RoboStack 用 conda 装 Humble

在 24.04 上用 conda-forge 的 `ros-humble-desktop`，系统不用动。代价是 ROS 装进 conda 环境后，**所有 C++ 依赖（PCL、tf2）也来自 conda**，和 `apt` 装的 PCL 容易混；且 `colcon build` 时的 CMake 路径要找 conda 的那一套。对"只想跑回放"够用，对实机不推荐。

### 无论走哪条路都要改的地方（代码里写死了 humble）

我扫了一遍仓库，`humble` 硬编码在这些位置：

| 文件 | 位置 | 说明 |
|---|---|---|
| `start_fusion.sh` | L27 `require_file`、L35、L47 | 三处 `/opt/ros/humble/setup.bash` |
| `tools/synchronized_replay.py` | L374、L467、L532 | **回放启动器**：拼接 shell 脚本时写死；L467 还是报错提示文案 |
| `record.sh` | L63、L65 | 录制脚本 |
| `Main_ws/run_scripts/run_referee_web_injector.sh` | L13、L15 | 裁判网页注入工具 |

还有一处**不在 humble 上但同样会坑**：`synchronized_replay.py` L532 里 `conda activate cud128` 是写死的环境名。

建议的做法不是逐个替换成 `jazzy`，而是改成：

```bash
ROS_SETUP="${ROS_SETUP:-/opt/ros/$ROS_DISTRO/setup.bash}"
```

这样两条路都能用，也不影响别人在 22.04 上跑。

### 风险评估

| 部分 | 24.04 上会不会坏 | 说明 |
|---|---|---|
| ROS2 C++ 三个节点 | 大概率能编译 | PCL 1.14 / gcc-13 下没见到会报错的写法；但要重新 `colcon build` 验证 |
| `localization` 配准行为 | **需要实测** | 换了 PCL 版本，GICP/NDT 的数值结果可能有微小差异，重新标定 |
| lidar 管线 | 低风险 | 纯 PCL + TF |
| Python 融合层 | 低风险 | 纯 numpy/scipy，与发行版无关 |
| 相机 MVS SDK | **实测可用** | 用户已在 24.04 上验证 MVS 能跑；具体差异未记录，但不再是阻塞项 |
| TensorRT / CUDA | 没问题 | CUDA 12.5+ 起官方支持 noble |
| Qt / RViz | 没问题 | 但要 X11 会话 |
| 那个 libusb 冲突 | **更容易复发** | `synchronized_replay.py` 里有一段 `LD_PRELOAD` 系统 libusb 的 hack（注释说 MVS 自带旧 libusb 会被优先选中，而 PCL 需要系统版）。换系统后这层依赖更脆弱 |

### 结论

如果目的是**学习 + 跑回放**：直接用容器，别折腾系统。

如果必须**在 24.04 裸机上实机运行**：走 Jazzy，但要接受三件事——重写那 4 个脚本里的 ROS 路径、把 conda 环境升到 3.12、重新验证配准精度。这已经不是"改一改"，而是一次移植。**具体操作步骤见 [11-迁移到Ubuntu2404.md](11-迁移到Ubuntu2404.md)。**

（相机 MVS 已在 24.04 上实测可用，所以这块不再是障碍。）

如果只是想省事又不想用容器：**装一台 22.04 的双系统或旧笔记本**，比移植便宜得多。

## 14. 国内网络：镜像与断点续传

这套环境的下载量很大（conda 安装包 120MB、PyTorch cu128 wheel 2–3GB、TensorRT 数百 MB），
**从官方源直连在国内常见只有几十 KB/s**，一个 torch 就能下一整天。所以先解决网络再开始装。

### 14.1 先做这件事：用 tmux

SSH 一旦断线，前台下载全部作废。所有耗时超过两分钟的操作都放进 tmux：

```bash
sudo apt install -y tmux
tmux new -s setup          # 新建会话
# 断线后重连：tmux attach -t setup
```

### 14.2 Miniforge 换清华镜像

```bash
wget -c https://mirrors.tuna.tsinghua.edu.cn/github-release/conda-forge/miniforge/LatestRelease/Miniforge3-Linux-x86_64.sh
bash Miniforge3-Linux-x86_64.sh -b -p ~/miniforge3
~/miniforge3/bin/conda init bash
```

`-c` 是断点续传，中断了重跑同一条命令即可接着下。

### 14.3 conda 换清华源

```bash
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge
conda config --set show_channel_urls yes
```

### 14.4 pip 换清华源

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 14.5 PyTorch：官方 wheel 不在 PyPI 上

这点要单独说明：**`pip install torch` 从 PyPI 装到的是 CPU 版**，CUDA 版只放在
`download.pytorch.org` 这个独立源上，所以 `index-url` 换成清华也没用——那个域名清华不镜像。

两个办法：

**A. 国内镜像（推荐先试）**

```bash
pip install torch torchvision --index-url https://mirror.sjtu.edu.cn/pytorch-wheels/cu128
# 或者
pip install torch torchvision --index-url https://mirrors.aliyun.com/pytorch-wheels/cu128
```

镜像不一定覆盖所有 CUDA 版本目录，404 就换下一个。

**B. 官方源 + 断点续传**

```bash
pip install --timeout 120 --retries 20 \
    torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

`pip` 自身不支持断点续传，但 `--retries` 会在断流后重试。更稳的做法是先用 `wget -c`
把 wheel 拉下来再本地安装：

```bash
# 先在镜像站或官网上找到确切的 wheel 文件名，然后
wget -c https://download.pytorch.org/whl/cu128/torch-2.7.0%2Bcu128-cp312-cp312-linux_x86_64.whl
pip install ./torch-2.7.0+cu128-cp312-cp312-linux_x86_64.whl
```

（版本号和文件名以 `download.pytorch.org/whl/cu128/torch/` 页面实际列出为准。）

### 14.6 判断装到的是不是 CUDA 版

```bash
python -c "import torch; print(torch.version.cuda)"
# 打印 12.8 → 是 cu128 版
# 打印 None → 装成了 CPU 版，需要卸载重装
```

### 14.7 如果你是通过 SSH 远程操作这台机器

最后一条很关键：**Qt 界面和 RViz 都需要图形界面**，纯 SSH 跑不起来。

三个选择，按体验排序：

| 方式 | 命令 | 说明 |
|---|---|---|
| 直接坐在机器前 | — | 最流畅，推荐用于调参和比赛 |
| VNC / x11vnc | `sudo apt install x11vnc` | 带宽需求中等，可接受 |
| X11 转发 | `ssh -X user@host` | **不推荐**：4024×3036 的图像和 RViz 点云会把带宽吃满，界面卡到没法用 |

如果只是**跑回放看结果**，X11 转发勉强能忍；要真调参，就用 VNC 或直接接显示器。
