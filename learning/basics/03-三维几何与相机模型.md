# 基础 03 · 三维几何与相机模型（从 solvePnP 到射线求交）

> 前提：你用 OpenCV 标定过相机（或至少知道 `cv2.calibrateCamera` 会给出内参）、
> 听说过 `cv2.solvePnP`。这篇把这些零件拼成完整链路：像素 ⇄ 场地坐标。
> 这是全项目数学最重的一篇，但每一小步你都见过一半。

## 1. 内参 K：相机自带的「像素换算表」

针孔模型：三维点 `P_cam = (X, Y, Z)`（相机坐标系，Z 朝前）成像在

```text
u = fx · X / Z + cx        fx, fy: 焦距（单位是像素！）
v = fy · Y / Z + cy        (cx, cy): 光轴中心（约等于图像中心）
```

写成矩阵就是 `device.yaml` 里那张 `camera_matrix`：

```yaml
camera_matrix: [3299.53,    0,   2024.06,     # fx = 3299.5 px
                0,   3300.89,   1609.15,      # fy = 3300.9 px（和 fx 几乎相等=方形像素）
                0,      0,      1]            # 光心 ≈ (2024, 1609)，恰是 4024×3036 的中心
```

- `fx=3300 px` 意味着水平视场 `2·atan(2012/3300) ≈ 62.6°`——6mm 镜头的典型值。
- **除以 Z 就是透视**：同样 1 米宽的车，10 米远占的像素宽度是 5 米远的一半。
  实验图里地面点阵「越远越密」就是这个公式。

畸变系数 `dist_coeffs`（5 个数，k1,k2,p1,p2,k3）描述真实镜头偏离针孔的程度：
径向畸变让直线变弯（广角边缘桶形畸变），切向畸变来自透镜组装偏心。
**边缘畸变可达上百像素**（实验 2 实测），所以一切几何计算前必须
`cv2.undistortPoints` / `cv2.undistort` 去畸变。

## 2. 外参 R, t：相机和世界怎么对上

内参描述相机内部，**外参描述相机相对世界的摆放**：

```text
X_cam = R · X_world + t        （世界 → 相机）
```

- `R`：3×3 旋转矩阵（正交，行列式 = 1）；
- `t`：平移向量，**注意它不是相机位置**！相机在世界系的位置是 `-R.T @ t`
  （把「世界→相机」反过来解）。这个坑在 `ray_renderer.py` 里就写着：
  `origin = -R.T @ T`——相机光心。

旋转的三种表示你都会遇到，互相转换一行代码：

| 表示 | 形状 | OpenCV | 出现在哪 |
|---|---|---|---|
| 旋转矩阵 | 3×3 | `cv2.Rodrigues(rvec)` 互转 | 最终参与计算的形态 |
| 旋转向量 | 3×1（轴×角） | `solvePnP` 的返回值 | PnP 输出 |
| 四元数 | 4 个数 | 手写或 `scipy` | TF 消息 `transform.rotation` |

外参**不是仓库里写死的**：雷达站每天架设位置不同，项目在启动后由操作员点
场地关键点、`cv2.solvePnP` 现场解出（见下文第 4 节和实验 3）。

## 3. 齐次坐标与 4×4 变换矩阵

把「旋转 + 平移」拼成一个矩阵乘法：

```text
[X_cam]   [R  t] [X_world]      device.yaml 里 lidar.extrinsics 就是这个 4×4：
[Y_cam] = [0  1] [Y_world]       -0.021  -0.9998  0.0043  -0.0265
[Z_cam]          [Z_world]       -0.019  -0.0039 -0.9998  -0.0350
[1   ]          [1     ]          0.9996 -0.0214 -0.0188  -0.0142
                                         0       0       0     1
```

好处：**链式变换 = 矩阵连乘**，逆变换 = 矩阵求逆。雷达系点 → 场地系点 →
相机系点，就是 `T_cam_field = T_cam_lidar · T_lidar_field` 一行的事。
TF 广播的也是这类变换（拆成 quaternion + translation 存储）。

## 4. solvePnP：已知 3D 点和对应像素，解外参

你有 4+ 组「世界坐标 ↔ 图像像素」对应（项目里是 `transform/keypoints.txt`
预存的场地关键点 + 操作员手点的像素），PnP 解出 `R, t`：

```python
ok, rvec, tvec = cv2.solvePnP(object_points_3d, image_points_2d, K, dist)
```

项目用两步（`transform/solvepnp.py`）：`solvePnPRansac(EPnP)` 粗解抗外点 →
`solvePnP(ITERATIVE)` 用结果当初始值精修。实验 3 完整复刻了这条链，并给出关键
数字：**1.5 px 的点选噪声 → 相机位置误差 0.6 cm、场地反投影误差 1~7 cm**。
这就是为什么宁可让操作员每天手点几十个点，也不用卷尺量外参（量出来误差是米级）。

## 5. 逆投影：从像素到场地（本项目的方向）

项目主链路不是「3D→2D」而是反过来：**检测框在像素 (u, v)，问它落在场地哪个 (x, y)**。

```python
# transform/ray_renderer.py 的 4 步（20 行的完整版在原文件）：
und = cv2.undistortPoints((u, v), K, dist, P=K)      # 1) 去畸变（仍是像素）
d_cam = np.linalg.inv(K) @ [und_u, und_v, 1]          # 2) 乘 K⁻¹ → 相机系方向（关键一步！）
d_world = R.T @ d_cam                                 # 3) 方向转到世界系
origin  = -R.T @ t                                    #    光心位置
# 4) 从 origin 沿 d_world 发射线，和场地网格求交 → 交点就是 (x, y)
```

一个像素只确定一条**射线**（无数个深度都投影到同一像素），所以必须靠「打到的
地面/墙」来定深度——这就是为什么项目要带一张场地三维网格 `RMUC2026.ply`
（实验 1 读的就是它），用 open3d 的 `cast_rays` 批量求交。

⚠️ 两个固有限制（读到项目代码时不困惑）：

- 交点可能是**墙**不是地面：车贴墙时，框底边中心打到车后面的墙上，位置就偏了；
- 每个像素求交太慢，项目用 `xy_map.py` 把场地平面预栅格化成「XY Map」加速查表。

## 6. 旋转的部分一眼看不出？给你个检查技巧

单位化检查：`R @ R.T ≈ I`、`det(R) ≈ 1`；平移量级检查：单位是米，场地对角线
约 32 m，看到 `t` 的模长是几就合理。拿这套检查去看 `device.yaml` 的
`lidar.extrinsics`（4×4），能自己验证它确实是个刚体变换。
