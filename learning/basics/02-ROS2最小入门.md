# 基础 02 · ROS2 最小入门（只学这个项目需要的部分）

> 前提：你写过 `python xxx.py` 跑 OpenCV 脚本。ROS2 官方教程有几百页，
> 这篇只讲读懂本项目必须的 6 个概念 + 10 条命令，约 1 小时。

## 1. 为什么要有 ROS2

你写 OpenCV 脚本时，一切都在一个进程里：`img = cap.read()` 拿图，处理，`imshow`。

本项目不一样：**点云管线是 C++ 写的（要跑 PCL），视觉主程序是 Python 写的
（要跑 PyTorch/Qt），它们是两个独立进程，还可能在不同电脑上**。总得有个东西
负责「进程 A 把点云发给进程 B」。ROS2 就是机器人圈的标准答案——它提供：

- **通信**：谁都能发消息、谁都能订阅，不用自己写 socket；
- **生态**：雷达厂商（Livox）、可视化工具（RViz）、录制回放（rosbag）、坐标变换
  服务（TF）全是现成的 ROS2 组件；
- **约定**：node / topic / message 这套词汇，让不同队伍的代码能拼在一起。

一句话：**ROS2 之于机器人 = 「消息队列 + 插件生态」**，算法本身不含任何魔法。

## 2. 六个概念，每个一句话 + OpenCV 类比

| 概念 | 一句话 | 类比 |
|---|---|---|
| **Node（节点）** | 一个进程里的一个模块，有名字 | 一个 `.py` 脚本 |
| **Topic（话题）** | 一条命名的广播频道，如 `/livox/lidar` | 一个无限长的队列，生产者 push，消费者 pop |
| **Publisher / Subscriber** | 往频道发消息 / 从频道收消息 | `cap.read()` 的两边：驱动发帧，你收帧 |
| **Message（消息）** | 频道里传的数据结构，字段固定 | `dict`，但 schema 提前定义好（如 `PointCloud2`） |
| **Launch** | 一个脚本同时拉起多个节点并传参 | `bash` 里写多行启动命令的 YAML 版 |
| **TF（变换树）** | 全局公告板：谁都能查询任意两个坐标系之间的变换 | 一个共享的 `R, t` 字典，自动随时间更新 |

### 2.1 Topic 的关键性质：异步、最新者胜

订阅者的回调在**独立线程**里被触发，发布者不等人。如果处理慢，中间件（DDS）
默认策略下旧消息可能被丢弃——这和你用 `cap.grab()` 跳帧拿最新画面是一个道理。
本项目 Python 侧订阅聚类话题就是这么设计的：永远只缓存「最新一份快照」
（`ros2_lidar_client.py`），点云处理不过来没关系，反正下一帧马上来。

### 2.2 TF 值得多说两句

「雷达坐标系 → 场地坐标系」的变换 `rm_frame → livox_frame` 由 localization 节点
算出来后**广播到 TF**，dynamic_cloud 每帧 `lookupTransform` 去查。
为什么不在消息里直接带上变换？因为 TF 支持**带时间戳的查询**（「0.1 秒前那帧
点云时刻的变换是多少」），且多个传感器、多级坐标系（雷达→云台→底盘→场地）
能拼成一棵树统一管理。

本项目的 TF 是**硬依赖**：`dynamic_cloud` 查不到 TF 就整帧丢弃（不降级），
所以 localization 一挂，整条雷达链路就断——排查问题时先看它。

## 3. 十条命令（在本机装好 ROS2 后可用）

```bash
source /opt/ros/humble/setup.bash    # 每个终端都要先做，否则命令都找不到

ros2 node list                       # 现在有哪些节点在跑
ros2 topic list                      # 有哪些话题
ros2 topic info /livox/lidar         # 这个话题谁在发、谁在收、什么类型
ros2 topic echo /livox/lidar_cluster # 把消息内容打印出来（调试神器）
ros2 topic hz  /livox/lidar          # 实测话题频率（雷达是不是真的 10Hz？）
ros2 run rviz2 rviz2                 # 打开 3D 可视化
ros2 bag play xxx.db3                # 回放录制的 rosbag
ros2 bag record /livox/lidar         # 录制某个话题
ros2 param list /cluster_node        # 查某节点的参数
```

没有雷达硬件时，`topic echo/hz` 配合项目提供的回放数据（`recordings/`）就能全部练一遍，
见 [../08-调试与验证.md](../08-调试与验证.md)。

## 4. rclpy 十五秒入门（Python 侧怎么收消息）

本项目 `Main_ws/driver/lidar/ros2_lidar_client.py` 的骨架就长这样：

```python
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import PointCloud2

class LidarClient(Node):
    def __init__(self):
        super().__init__("lidar_client")          # 节点名
        self.create_subscription(                 # 订阅一个话题
            PointCloud2, "/livox/lidar_cluster",
            self.on_cloud, 10)                    # 回调 + 队列长度
        self.latest = None

    def on_cloud(self, msg: PointCloud2):         # 消息来了就进这里（独立线程！）
        xy = read_points_xy(msg)                  # 解包 x,y 字段
        self.latest = xy                          # 只留最新，处理不过来就丢旧的

rclpy.init()
node = LidarClient()
rclpy.spin(node)                                  # 阻塞式事件循环，等回调
```

和你熟悉的 `while True: ret, frame = cap.read()` 对比：**拉模式变推模式**。
「读一帧」变成「注册一个回调等着被叫」。

`PointCloud2` 消息本体是「一坨字节 + fields 描述」，`sensor_msgs_py.point_cloud2`
里的 `read_points` 能帮你解成 numpy。Python 侧不需要理解 DDS、QoS 这些深水区，
能看懂上面的骨架就够读全部 `Main_ws/driver/` 了。

## 5. rosbag2：机器人的「录像机」

- `ros2 bag record /livox/lidar` = 录像：把话题上流过的每条消息**连同时间戳**存盘；
- `ros2 bag play xxx` = 回放：按原时间节奏把消息重新发到话题上。

下游节点完全分不清消息来自真雷达还是回放——这就是本项目「回放验证」的原理：
`tools/synchronized_replay.py` 同时回放 rosbag（点云）和相机录像（视频），
让整条管线在没有硬件的机器上跑起来。`recordings/replay_sample/` 里那份
7 秒样例就是第一次练手用的（先跑 `--preflight-only` 见根目录 README）。

## 6. 本项目的进程拓扑（背下来）

```text
ros2 launch rm2026_lidar_launch lidar_pipeline.launch.py     ← Lidar_ws（C++）
    ├─ livox_ros_driver2        发 /livox/lidar（可外部启动时跳过）
    ├─ localization             配准，发 TF + /livox/map
    ├─ dynamic_cloud            扣静态，发 /livox/lidar_dynamic、/livox/lidar_fly
    └─ cluster                  聚类，发 /livox/lidar_cluster（+ fly_cluster）

python main.py                                                ← Main_ws（Python）
    ├─ LidarClient ×2         订阅两个 cluster 话题
    ├─ 相机/回放线程、A/B 视觉流水线、Qt 界面
    └─ 融合输出 → 裁判串口 / UI
```

完整版（含线程模型和每个话题的字段）见 [../02-架构与数据流.md](../02-架构与数据流.md)。

## 7. 怎么读 Lidar_ws 里的 C++ 节点

你不需要会写 C++，只需要认得三个模式，任何 ROS2 节点都长这样：

```cpp
// ① 订阅：收到消息进入回调（对应 Python 的 create_subscription）
sub_ = this->create_subscription<PointCloud2>(
    "/livox/lidar", 10,
    [this](const PointCloud2::SharedPtr msg) { this->on_cloud(msg); });

// ② 发布：往话题发消息
pub_ = this->create_publisher<PointCloud2>("/livox/lidar_cluster", 10);
pub_->publish(msg);

// ③ 参数：从 yaml 里读配置（params.yaml 里那一大坨就这么被读走）
this->declare_parameter("cluster_tolerance", 0.5);
tol_ = this->get_parameter("cluster_tolerance").as_double();
```

带着这三个模式去读 `localization.cpp` / `dynamic_cloud.cpp` / `cluster.cpp`，
你会发现剩下的全是 PCL 算法调用——而那些算法的直觉你在基础 01 和实验 4/7 里
已经建立过了。
