# 基础 05 · 卡尔曼滤波与数据关联（融合的心脏）

> 前提：会 numpy 矩阵乘法。这篇从零建立两个直觉：「怎么把带噪声的测量变平滑、
> 还能预测未来」和「怎么决定哪条测量属于哪个目标」。它们合起来就是
> `tracker/CascadeMatchTracker/` 在做的事。

## 1. 问题：雷达给的位置在抖

雷达每 0.1 s 给一个聚类中心。让车原地不动，测到的是：

```text
17.42, 6.31 → 17.68, 6.05 → 17.21, 6.44 → ...    （0.2~0.3 m 的随机抖动）
```

裁判系统要的是稳定坐标 + 目标丢失时还能续着报。两件事分别对应
**滤波**（去抖）和**预测**（外推）——卡尔曼滤波一把全包。

## 2. 十分钟直觉推导（不背公式版）

### 2.1 先看一维的最简情形

你有一个预测值 `x_pred`（不确定度 `p_pred`）和一个测量值 `z`（不确定度 `r`）。
两个信息源怎么融合？——**按置信度加权平均**：

```text
K = p_pred / (p_pred + r)        # 0~1 之间。预测越不可信，K 越接近 1
x_new = x_pred + K · (z - x_pred)
```

- `K→1`：完全信测量（预测太不靠谱）；
- `K→0`：完全信预测（测量噪声太大）。

这就是卡尔曼滤波的全部灵魂：**增益 K 在「信模型」和「信测量」之间动态找平衡**。
剩下的公式只是把它推广到多维（用协方差矩阵代替方差）。

### 2.2 匀速模型：把「车怎么动」写成矩阵

状态取 `[x, y, vx, vy]`（位置 + 速度）。假设短时间内匀速（dt 内位置加 dt·v）：

```text
      F = [[1,0,dt,0],        H = [[1,0,0,0],      x' = F @ x        (预测)
           [0,1,0,dt],             [0,1,0,0]]      z  = H @ x + 噪声 (只能测到位置)
           [0,0,1,0 ],
           [0,0,0,1 ]]
```

四个噪声/不确定度矩阵（调参就调它们）：

| 矩阵 | 含义 | 调大的效果 |
|---|---|---|
| `P` | 当前状态的不确定度 | 初始设 100（=「我一无所知」），跑几帧自己收敛 |
| `Q` | 模型噪声（车会急转急刹，匀速假设不完美） | 更信测量、响应快但抖 |
| `R` | 测量噪声（雷达抖多少米） | 更信预测、平滑但滞后 |
| `H` | 能测到什么 | 本项目只测位置，H 把速度「藏」在模型里推出来 |

predict / update 循环只有 8 行，和项目 `kalman.py` 里那个 4×4 的
`KalmanFilter2d` 一模一样（实验 5 是它的可运行复刻）：

```python
def predict(self):
    self.x = F @ self.x
    self.P = F @ P @ F.T + Q

def update(self, z):
    y = z - H @ self.x            # 残差：测量比预测多出多少
    K = P @ H.T @ inv(H @ P @ H.T + R)
    self.x = self.x + K @ y
    self.P = (I - K @ H) @ P      # 更新后不确定度一定变小
```

**副产品最有用**：`F @ x` 一推，就得到未来任意时刻的位置预测——
目标被挡住、雷达暂时没测到时，靠它「续航」。项目的丢失降级三档
（`params.yaml: loss.*`）：

```text
丢 < 10 帧   纯卡尔曼 predict 续航（本篇的内容）
丢 ≥ 10 帧   允许用雷达聚类点直接猜（radar_guess）
丢 ≥ 30 帧   退化为 guess_pts.yaml 里的固定出生点（fixed_guess）
```

### 2.3 项目里谁在用

每个身份（B1~R7 共 10 个）一个 `KalmanFilter2d`：

- **测量**优先用雷达聚类中心（`R = lidar_r_std_m = 0.20 m`，因为准）；
- 匹配失败时退化用视觉投影点（`R` 放大，表示更不信）；
- 误差超 `hard_reset_distance_m = 2.5 m` 时整个滤波器推倒重建
  （`hard_reset`，防止错误匹配把状态拖去十万八千里）。

## 3. 数据关联：测量来了，更新谁？

第 2 节默认知道「这个测量属于这个滤波器」。实际上每帧同时有：
3 个卡尔曼的预测位置、5 个雷达聚类中心——谁配谁？

```text
1) 建代价矩阵 C[i][j] = 轨迹 i 预测位置与聚类 j 中心的距离（米）
2) 匈牙利算法求「总代价最小」的一对一分配
3) 逐对检查距离 ≤ 门限（彩色身份 1.5 m、历史续接 2.0 m），超门限 = 拒配
4) 拒配/没分到的 → 走降级链（换下一级更宽松的匹配规则再试）
```

匈牙利算法不用会写（`scipy.optimize.linear_sum_assignment` 一行），但要知道
**为什么必须用它而不能贪心**：每个轨迹各自挑最近的聚类，会出现两个轨迹抢
同一个点（实验 6 有实例）。贪心是局部最优，匈牙利保证全局最优。

「级联」是项目的工程化加强：按身份可信度从高到低排队——带彩色身份的视觉轨迹
先挑、历史轨迹次之、纯雷达轨迹垫底，每一级内部再做一次匈牙利。九级细节在
[../06-融合状态机.md](../06-融合状态机.md)，此处只需记住设计哲学：**由严到宽、
逐级兜底**，最严的匹配用掉最好的资源，剩下的留给更宽松的规则。

## 4. 一图串起融合层

```text
视觉: 车框 → 装甲 → 数字 →「R3 大概在 (17.9±1.5) m」  (身份准, 位置粗)
雷达: 聚类中心列表「(17.4,6.4) (23.0,2.0) ...」        (位置准, 没身份)
                 │
   级联匹配: 视觉投影点挑最近的雷达点, 匈牙利+门限
                 │
   匹配成功 → 雷达点作为测量 update 卡尔曼 (位置准)
   匹配失败 → 降级链: 历史匈牙利 → 灰甲模糊 → 纯雷达猜 → KF续航 → 固定点
                 │
   10 个身份的 [x, y, vx, vy] → UI / 裁判系统
```

这也呼应 [../README.md](../README.md) 里那条「隐藏主线」：雷达给位置、相机给身份、
融合就是把两者在场地平面上对齐。
