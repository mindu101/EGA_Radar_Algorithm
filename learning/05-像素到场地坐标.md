# 05 · 从像素到场地坐标

这篇讲三件事：**相机射线怎么打到地上**、**怎么加速**、**红蓝阵营的坐标怎么统一**。

对应代码：`transform/ray_renderer.py`、`transform/xy_map.py`、`transform/solidwork2uwb.py`、`transform/solvepnp.py`。

## 1. 为什么需要这一步

融合的核心思想是：**在场地平面上比较距离**。

A 车在图像里的 (1523, 2044)，单位是像素；雷达给出 (18.3, 6.2)，单位是米。两者没法直接比距离。
所以要把像素换算成米——而且必须换算到**和雷达同一个坐标系（`rm_frame`）**。

作者的原话（`docs/融合定位算法说明.md` 5.1 节）值得引用：

> 考虑到相比于相机平面，场地平面的距离度量天然一致且良好，也可以自然地使用卡尔曼滤波的结果。故我们将匹配过程的距离度量放于场地平面上。

## 2. 相机模型与标定

### 2.1 内参从哪来

`params.yaml: transform`：

```yaml
K: [[3299.5283, 0,        2024.0633],
    [0,        3300.8857, 1609.1451],
    [0,        0,        1        ]]
dist_coeffs: [-0.0581, 0.0953, 0.00095, -0.00118, -0.0524]
```

这是海康 MV-CS120 的标定结果（`params.yaml` 里还有多组被注释掉的内参，对应 CS060、T-DT 等不同相机，切换相机时改这里）。

### 2.2 外参从哪来：每次架设现场标定

`R` / `t` **不是**固定写在配置里就完事，而是**由界面标定生成**：

```text
操作员在 UI 里点场地上的已知关键点（transform/keypoints.txt）
        ↓
cv2.solvePnPRansac(flags=EPNP, reprojectionError=6.0)
        ↓
cv2.solvePnP(flags=ITERATIVE, 用 RANSAC 结果当初值) 精修
        ↓
Rodrigues(rvec) → R, t
        ↓
MainEventLoop.set_calibrated_param(R, t)
        ↓
PixelToWorld.build_from_config_and_extrinsics(...)  ← 重建投影器
```

流程细节在 `solvepnp.py` 的 `PnPSolver.solve()` 和 `interface/core.py` 的 `KeypointCalibrationDialog`。
标定结果会存成 `latest.txt` 之类的外参记录文件，回放时可以直接导入（`RM_EXTRINSICS_IMPORT_PATH` 环境变量），不用重新标。

**这一步为什么必须在环（human-in-the-loop）**：雷达站每次架设的高度、俯仰、朝向都不同，用卷尺量出来的外参误差在几米级别，而 PnP 用 4 个以上场地关键点就能把误差压到厘米级。

### 2.3 标定结果怎么传播

`set_calibrated_param()` 做的事比看上去多：

```python
self.pixel_world_transform = PixelToWorld.build_from_config_and_extrinsics(...)
self.tracker.pixel_world_transform = self.pixel_world_transform   # 给检测器
self.reset_projection_lidar_statistics("外参更新")                 # 清空残差统计
self.xy_map_manager.set_calibration(self.pixel_world_transform)   # 触发 XY Map 重建
self._advance_pipeline_epoch("相机外参整体替换")                    # 让在途包失效
```

最后一行很关键：**外参一变，所有在途的旧帧都可能用旧外参算过投影，必须全部作废**。epoch 机制在这里复用得非常自然。

## 3. 射线求交：`PixelToWorld.pixel_to_world()`

`ray_renderer.py` L100，一共 20 行，是整个投影的核心：

```python
# 1) 畸变校正
points = np.array([[u, v]], np.float32).reshape(-1, 1, 2)
undistorted = cv2.undistortPoints(points, K, dist, P=K)
u, v = undistorted[0, 0]

# 2) 像素 → 相机坐标系方向
pixel_hom = np.array([u, v, 1.0])
cam_dir = np.linalg.inv(K) @ pixel_hom

# 3) 相机坐标系 → 世界坐标系
world_dir = R.T @ cam_dir
origin   = -R.T @ T.flatten()

# 4) 投射射线，找与场地网格的交点
result = scene.cast_rays(Tensor([[*origin, *world_dir]]))
t_hit = result["t_hit"].numpy()[0]
hit = origin + t_hit * world_dir
```

几个值得注意的点：

- **`world_dir` 没有归一化**。这是对的——Open3D 的 `cast_rays` 返回的 `t_hit` 就是"以传入方向为单位"的参数，所以 `origin + t_hit * world_dir` 直接得到交点，不需要再除模长。
- **`origin = -R.T @ T`**：这是把 `X_world = R·X_cam + T` 反解出相机光心在世界坐标的位置。
- **交点可能是墙**。射线打到哪里取决于网格模型。如果底边中心正好落在车辆后面的墙上，得到的坐标就不是地面点——这是这类方法的固有误差源。

### 3.1 场地网格

网格来自 `field/RMUC2026.ply`（Open3D `RaycastingScene`，`max_octree_depth=8`）。

这个网格是「场地表面」的三维重建：地面 + 部分立起来的结构。射线求交比"假设地面是平面 z=0"要准得多，因为实际场地有坡度、有台阶、有道具。

**代价**：如果车辆投影点落在了一个立面上（比如柱子），会得到明显偏离的点。所以后续匹配一律用"门限 + 互斥求解"来吸收这类离群值，而不是相信单个投影点。

### 3.2 三角剖分可视化

`PixelToWorld.__init__` 里还额外构造了 `edge_lineset`（把三角面片的所有边提取出来），是给标定 GUI 用的，和计算无关。读代码时可以跳过。

## 4. XY Map：把每帧的射线计算提前摊掉

### 4.1 问题

`pixel_to_world` 每帧要为每辆车算一次射线求交。虽然只有 10 次，但它牵扯 Python 循环 + Open3D 调用，在 30Hz 下依然可观。

### 4.2 方案

`xy_map.py::XYMapManager` 的思路是：**给定 (图像尺寸, 相机内外参) 之后，每个像素对应的场地坐标是一个确定的函数**。所以可以：

1. 在后台线程把整幅图（或降采样后的图）的每个像素都算一遍，存成两张查找表 `X[u,v]`、`Y[u,v]`。
2. 实际使用时只是一次数组索引。

```text
标定完成 / 分辨率变化 (signature 变化)
        ↓ 触发后台重建
逐行批量射线投射（generation_chunk_rows=64）
        ↓
生成 float32 的 X/Y 查找表
        ↓
project_pixel(u, v)  →  查表（lookup_mode: nearest）
```

### 4.3 关键设计

| 设计 | 作用 |
|---|---|
| **异步构建**（`_build_worker`） | 不阻塞主循环；构建期间自动回退到直接投影 |
| **generation 计数** | 标定变了之后，旧表的构建结果会被丢弃 |
| **`signature`** | 由（分辨率 + 标定）生成，只有真正变化才重建 |
| **一致性校验**（`consistency_check`） | 随机抽 10 个像素，与直接射线求交比对，误差 > 0.10m 就报警 |
| **`invalid_value: "nan"`** | 未命中网格的像素存 NaN，查表时自然被判为无效 |

一致性校验是很好的工程细节：**加速路径必须有验证机制**，否则一旦 XY Map 因为内存布局或索引错误而偏了，整个融合会静默失效。

### 4.4 默认是关闭的

```yaml
ray_projection:
  xy_maps_default_enabled: false
```

默认走实时射线求交（更简单、绝对正确），UI 里可以手动开启 XY Map。开启后可以在耗时统计里看到模块 09.3 明显下降。

**如果你要做二次开发**：这里是性能优化的首选入口。改 `xy_map.py` 的构建策略（比如只对 ROI 区域建表）比优化别的地方收益更大。

## 5. 阵营镜像：`solidwork2uwb()`

`transform/solidwork2uwb.py` 全文只有 15 行，但它是理解整个融合层坐标的钥匙：

```python
def solidwork2uwb(pos_3d, faction=FACTION.RED):
    x, y, z = pos_3d
    if faction == FACTION.RED:
        pos_x, pos_y = x, y
    else:
        pos_x, pos_y = 28.0 - x, 15.0 - y
    return pos_x, pos_y
```

（`solidwork` 指 SolidWorks 建模的场地坐标系，`uwb` 指裁判系统用的场地坐标系。）

### 为什么要有这一步

比赛里红方和蓝方的「我方/敌方」是镜像的。如果不做统一，融合逻辑就得写两套（红方视角一套、蓝方视角一套），非常容易出 bug。

做法是：**把所有坐标都转换到「己方视角」**，即「坐标小的一端永远是我方基地」。蓝方运行时做 180° 中心对称：

```text
x' = 28.0 - x
y' = 15.0 - y
```

雷达点也做同样处理（`tracker.py::_prepare_frame_inputs()`）：

```python
if faction == FACTION.BLUE and self.lidar_config.get("mirror_for_blue", True):
    x, y = field_length - x, field_width - y
```

于是无论红方蓝方，融合逻辑**只有一套**。

### 坐标系全景

| 坐标系 | 用途 | 谁在用 |
|---|---|---|
| `livox_frame` | 雷达自身 | 只到 localization 为止 |
| `rm_frame` | 场地全局（米） | ROS2 全部话题、TF |
| SolidWorks / 世界坐标 | 射线求交输出 | `PixelToWorld` 返回值 |
| **己方视角坐标** | **融合层内部** | `CascadeMatchTracker`、UI、`Radar2ClientMessage` 的 enemy_* 字段 |

### ⚠️ 一个真实的坑：硬编码的 28.0 / 15.0

`solidwork2uwb()` 里的 `28.0` 和 `15.0` 是**字面量**，而其他地方的场地尺寸来自配置：

```yaml
lidar_fusion:
  field_length: 28.0
  field_width: 15.0
```

目前两者一致，所以没问题。但如果你换了场地尺寸：

- `_prepare_frame_inputs()` 会用 config 的值（正确）。
- `solidwork2uwb()` 会用硬编码 28/15（**错位**）。

结果就是视觉投影点和雷达点对不上，而且不会有任何报错——这种静默错误最难查。
**如果要做二次开发，第一件事就是把这个函数改成读配置。**

## 6. 投影点在系统里的真实地位

这点必须说清楚，否则会误解算法：

> **投影点不是最终位置，它只是"候选筛选器"。**

在状态机里它的唯一用途是：给定一个身份 `class_id` 和一个雷达点，判断「这个身份投影到地面的位置，离这个雷达点有多远」，作为代价函数的一项。

```text
彩色匹配代价 = 2.0 × (1 - 组合置信度) + 6.0 × (投影点到雷达点距离 / 门限)
```

最终输出位置来自**雷达点**（经卡尔曼平滑），不是投影点。投影点的误差（标定残差 + 地形模型误差 + 底边中心近似）不需要很小，只要"足够筛选"即可，门限设到了 1.5m。

这个设计选择是整套算法的关键：**把相机用在它擅长的地方（分类），把雷达用在它擅长的地方（测距）**。

## 7. 自检：投影偏了怎么查

| 步骤 | 做法 |
|---|---|
| 1 | 打开 UI 的场地图，看投影点（通常画成另一种颜色）是否整体偏移 |
| 2 | 如果**整体**偏移 → 外参标定有问题，重新标定 |
| 3 | 如果**随距离增大**偏移 → 内参（畸变）不准 |
| 4 | 如果只有**远处/近处**特定区域偏 → 场地网格模型问题（该处 PLY 与实物不符） |
| 5 | 看 `get_projection_lidar_statistics_text()` 的均值残差，正常情况下应该在 0.2–0.5m 量级 |

第 5 条对应的 `projection_lidar_statistics.py` 会在线统计"高可靠匹配"的投影—雷达残差，是判断标定质量最直接的量化指标，见 [08-调试与验证.md](08-调试与验证.md)。
