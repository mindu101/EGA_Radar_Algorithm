# 09 · 术语表

按类别分组。每个词都标注了在**这个项目里**的具体含义，不是通用定义。

## ROS2 与点云

| 术语 | 英文 | 含义 |
|---|---|---|
| 配准 | Registration | 求实时点云与地图之间的刚体变换；本项目用 GICP + NDT |
| GICP | Generalized ICP | 广义迭代最近点。本项目当作**粗定位器**，精度封顶 10–20cm |
| NDT | Normal Distributions Transform | 正态分布变换。用高斯体素建模，精度高但依赖初值 |
| ndt_omp | — | 多线程 NDT 实现（`pclomp`），支持 `kdtree`/`direct26`/`direct7`/`direct1` 邻域搜索 |
| fitness | — | 配准质量分数，**越小越好**（本项目阈值 0.01） |
| 体素下采样 | Voxel Grid | 把空间切成小立方体，每格取代表点；本项目 leaf = 0.1m |
| 持久背景 | Persistent Background | 本项目特有：按方位角×俯仰角切格，每格保留**最远点**作为背景 |
| 空间栅格 | Grid | `background_angular_bin_deg = 0.1°` 的（方位角, 俯仰角）二维索引 |
| 内点率 | Inlier Ratio | 当前帧点落在背景栅格内的比例；低于 0.90 判定雷达被移动 |
| ROI | Region of Interest | 三维空间中的长方体区域，格式 `[x_min,x_max,y_min,y_max,z_min,z_max]` |
| 欧式聚类 | Euclidean Cluster Extraction | 按距离连通性分簇；本项目容差 0.25m |
| 聚类中心 | Cluster Centroid | 簇内点算术平均；**融合层拿到的就是它，不是点云** |
| KD-Tree | — | KD 树，用于最近邻查询（静态地图扣除） |
| TF | Transform | ROS2 坐标系变换；本项目关键的是 `rm_frame → livox_frame` |
| 话题 | Topic | ROS2 发布/订阅通道；见 [02-架构与数据流.md](02-架构与数据流.md) 的话题表 |
| 执行器 | Executor | ROS2 的 spin 循环；本项目每个 LidarClient 一个 `SingleThreadedExecutor` |
| 包 | Package | ROS2 软件单元；`localization`、`dynamic_cloud`、`cluster` 各是一个 |

## 视觉与检测

| 术语 | 英文 | 含义 |
|---|---|---|
| 两级检测 | Two-stage Detection | 先检车辆、再在车辆 ROI 内检装甲 |
| TensorRT engine | `.engine` | 序列化后的优化模型；**与 GPU 架构/CUDA/TensorRT 版本绑定** |
| NMS | Non-Maximum Suppression | 非极大值抑制；`iou_thres` 控制重叠框的合并 |
| LetterBox | — | 保持宽高比缩放到模型输入尺寸并补边 |
| BoT-SORT | — | 多目标跟踪算法；本项目用它给每辆车一个**跨帧 `track_id`** |
| ByteTrack | — | 另一种跟踪器（配置保留，未启用） |
| ReID | Re-Identification | 外观重识别；BoT-SORT 里**当前关闭** |
| 组合置信度 | Combined Confidence | `0.70 × 数字置信度 + 0.30 × 装甲置信度` |
| 身份锚点 | Identity Anchor | 可作为身份证据的观测；彩色门槛 0.30，灰甲门槛 0.40 |
| 语义候选 | Semantic Candidates | 一个观测可能的 `class_id` 元组；彩色 1 个，灰甲 2 个 |
| PnP | Perspective-n-Point | 用已知 3D 点 + 2D 像素求相机位姿；本项目用 RANSAC(EPNP) + ITERATIVE 精修 |
| 内参 | Intrinsics | `K`（焦距+主点）+ `dist_coeffs`（畸变） |
| 外参 | Extrinsics | `R`、`t`（相机相对场地的位姿） |
| 射线求交 | Ray Casting | 从相机光心发出射线，与场地 mesh 求交点 |
| 场地网格 | Mesh | `field/RMUC2026.ply`；Open3D `RaycastingScene` |
| 底边中心 | Bottom-Center | 车辆框的 `((x1+x2)/2, y2)`，用来近似地面接触点 |
| XY Map | — | 预计算的像素→场地坐标查找表，用于加速投影 |
| 投影模式 | Projection Mode | `DIRECT`（实时射线）或 `XY_MAP`（查表） |

## 融合与状态机

| 术语 | 英文 | 含义 |
|---|---|---|
| 级联匹配 | Cascade Matching | 按确定度从高到低分阶段匹配，前级占用后级不可用 |
| 三元组 | Triplet | `(class_id, car_index, lidar_index)` 的三元组合 |
| 互斥求解 | Disjoint Solve | 保证每个身份/车/雷达点本帧最多用一次的精确搜索 |
| 匈牙利算法 | Hungarian Algorithm | 二分图最优指派；本项目用 `scipy.optimize.linear_sum_assignment` |
| 虚拟列 | Dummy Column | 给匈牙利矩阵加列，允许某些行"选择不匹配" |
| 身份状态 | `identity_state` | `UNSEEN` / `GUESSED` / `CONFIRMED` |
| 空间状态 | `spatial_state` | `UNINITIALIZED` / `TRACKING` / `COASTING` / `LOST` |
| 位置来源 | `frame_source` | 本帧坐标从哪来；10 种，见 [06-融合状态机.md](06-融合状态机.md) 1.2 节 |
| 卡尔曼滤波 | Kalman Filter | 本项目是 4 维匀速模型 `[x, y, vx, vy]` |
| 硬重置 | Hard Reset | 直接重建滤波器（速度清零），而不是用增益拉过去 |
| 续航 | Coasting | 没有观测，靠卡尔曼外推输出位置 |
| 抢占标记 | Preempted | 猜测轨迹离某个"已被彩色匹配占用"的雷达点太近时打的标记，防止猜测污染确认 |
| 状态过期 | Stale | 数据包年龄超过 `max_commit_age_sec`（0.20s），禁止提交 |
| epoch | — | 流水线版本号；分辨率变化/时间戳回退/外参替换时 +1，使在途旧包失效 |
| latest-wins 邮箱 | Latest-wins Mailbox | 容量 1 的交接队列，新包直接覆盖未取走的旧包 |
| 固定点猜测 | Fixed Guess | 丢失 30 帧后，从 `guess_pts.yaml` 的常见驻留点里挑一个 |
| 阵营同分偏置 | Enemy Tie Bias | 红蓝代价几乎相等时（差 ≤0.15）偏向敌方 0.05 |
| 角色优先级 | Role Priority | 猜点时 `hero > standard_3 > standard_4 > sentry > engineer` |

## 工程与流水线

| 术语 | 英文 | 含义 |
|---|---|---|
| A 阶段 | Stage A | 取图 + 车辆检测 + BoT-SORT + 裁 ROI（轻） |
| B 阶段 | Stage B | 装甲/数字识别 + 融合跟踪（重） |
| `StageAPacket` | — | A 交给 B 的**不可变同源快照** |
| `CompletedFrame` | — | 一次成功提交后的**原子输出快照** |
| 原子提交 | Atomic Commit | 在锁内一次性替换所有输出字段，避免 UI 读到跨帧拼接 |
| 端到端延迟 | Processing Age | 帧进入 A 到模块 11 提交的时间 |
| 提交间隔 | Commit Interval | 相邻两次提交的时间差；**吞吐 = 1/间隔** |
| 在线统计 | Online Statistics | Welford 算法，逐点更新均值/协方差，不存历史样本 |
| 退化 | Degradation | 某个模块失败时保留能保留的信息继续跑 |
| 预热 | Warmup | 用固定图跑 10 次，让 TensorRT 完成首次 kernel 加载 |

## 命名的小历史

有几个名字有历史原因，看到不要困惑：

- **`solidwork2uwb`** —— `solidwork` 指 SolidWorks 建模坐标系，`uwb` 指裁判系统坐标系。现在实际上只是"阵营镜像"函数。
- **`pos_2d_uwb`、`pos_3d`** —— `TrackingState` 里的字段，`uwb` 是历史命名，含义就是场地坐标（米）。
- **`bot_id` vs `class_id`** —— `bot_id` 是 BoT-SORT 的跨帧物体 ID（不知道是谁），`class_id` 是机器人身份（0~14）。**两个完全不同的东西，代码里都叫 id，很容易看错。**
- **`PointGuesser` 的 `cos_factor: 0.003`** —— 极小，实际效果是"几乎纯按距离选"。别以为它是笔误。
