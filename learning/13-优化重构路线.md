# 13 · 优化与重构路线（RM2027 备赛）

> 分支 `perf/radar-first-wave` 的研究底稿。三个来源：对 Main_ws 视觉链路和
> Lidar_ws 雷达链路的逐文件代码审读、《RoboMaster2027 比赛规则手册 V1.0.0》
> （2026-10-15 版）逐节核对、以及本分支已实施并验证的第一批改动。
> 结论先行：**这个仓库的工程基础很好（指标体系、流水线设计都是上乘的），
> 优化的重点不是推倒重来，而是删掉死路径、把单位/接口的坑填平、
> 并按 RM2027 的新计分机制调整优先级。**

## 0. 一页纸结论

```text
已实施（本分支 4 个提交，全部验证过）:
  Python  ① 指标导出 NameError 修复  ② 数字预处理 numpy/cv2 批量化（14.0→5.6ms/40张）
  删减    ③ three_step 死路径整体移除（pfa_yolov5 副本+灯条分类器，-672KB/-168行）
  C++     ④ dynamic_cloud OpenMP 化+死代码删除+阈值单位改米；cluster 心跳+点数
最值得做的下一批（P0）:
  ① 核实 armor_best.engine 是否真支持 batch>10（一条 trtexec 命令就能验证）
  ② 裁判系统恒频发送改造 —— RM2027 每 0.5s 断流记一次「错误」，连续性直接扣分
  ③ RM2027 身份编码与场地地图适配（见第 3 节清单）
可读性长期工程:
  main_event_loop.py（2400+ 行）与 interface/core.py（6000+ 行）的拆解计划（第 5 节）
```

## 1. 基线：性能现状（代码审读结论）

### 1.1 视觉链路（Main_ws）

**做得好的（不要动）**：StageAPacket 只读视图零拷贝（`pipeline.py`）；GPU 上
NMS + 一次合并回传（`predictor.py:120-124`）；单槽 latest-wins 邮箱（`pipeline.py:182-238`）；
异步可视化先缩后画；NVENC 独立录像线程。**作者已布了 120 项模块级计时
（`get_pipeline_module_text()`），优化应顺着这些指标做减法，不要再加测量。**

瓶颈与机会（按影响排序）：

| # | 问题 | 证据 | 方向 |
|---|---|---|---|
| V1 | 装甲 engine 批量能力存疑：B 阶段按 N 个 ROI 组 batch，但转换脚本里 armor 的 `dynamic=True batch=10` 被注释 | `utils/convert_pt2tensorrt.py:28-38` | `trtexec --loadEngine=weights/local/armor_best.engine` 看输入 shape；不行就重导出 |
| V2 | 4024×3036 全图 CPU 硬拉伸到 1280×1280（纵横比失真 + 每帧 ~37MB 内存带宽） | `predictor_with_tracker.py:150-152` | letterbox 一步化 / GPU 预处理 / 4:3 输入 |
| V3 | RGB→BGR 负步长视图迫使框架内 `ascontiguousarray` 再复制一次 | `image_utils.py:19` | 相机端直接出 BGR 或 GPU 上翻通道 |
| V4 | 数字推理是 torch eager（torch.compile/TensorRT 被注释），模型小、launch 开销占比大 | `digit_classifier/predictor.py:37-51` | TensorRT 化或 CUDA Graph（本分支已把它的 CPU 预处理砍掉 2.5 倍） |
| V5 | 采集线程每帧 `cvtColor` 新分配 36.7MB，预分配 RingBuffer 被闲置 | `hik_camera/hik.py:559`、`:59-63` | `dst=` 写入固定槽位 |
| V6 | 4 个线程的 CPU 段互相抢核（可视化 30Hz 全图 resize、录像 RGBA 打包、BoT-SORT 纯 Python 段） | `async_visualization.py:298-300` 等 | 可视化降 10-15Hz；录像打包挪 GPU |

### 1.2 雷达链路（Lidar_ws）

| # | 问题 | 证据 | 方向 |
|---|---|---|---|
| L1 | 静态点剔除 = 每点一次 KD 树查询 + 每帧新建 12 线程 | `dynamic_cloud.cpp`（**本分支已改 OpenMP**） | 进一步：体素占位哈希 O(1) 查询，地图 leaf 放宽 0.2~0.3 |
| L2 | 配准 `max_registration=1` 锁定后，localization 仍每帧做全套背景维护（std::map 栅格 + 每帧重建 KdTree 查内点率）+ 双调试话题序列化 | `localization.cpp:607-738, 864-877` | 锁定后背景维护降 1~2Hz；`std::map` 换哈希；调试话题加开关 |
| L3 | 重定位策略过敏感：内点率 <0.90 即整轮重跑 GICP+双 NDT（CPU 尖峰 + TF 阶跃） | `params.yaml:74`、`localization.cpp:789-829` | 阈值降到 0.5~0.7 或连续 N 帧确认；或低频连续微调替代重置 |
| L4 | 同一张 PCD 两个进程各载各的下采样（内存×2、启动慢）；全链路 reliable QoS depth=10（慢消费积压 1s 而非尽早丢） | `localization.cpp:966-984`、`dynamic_cloud.cpp:342-355` | 预下采样入库单份加载；雷达链路 SensorDataQoS |
| L5 | cluster 输出仅有质心（本分支已加 intensity=点数）；多帧累积质心对高速目标有 0.3~0.6s 滞带 | `cluster.cpp:208-222` | 累积云按时间加权，中心偏向最新帧 |
| L6 | TF 硬依赖 + `TimePointZero` 取最新值；PCD 加载失败构造函数静默 return（下游整链假死） | `dynamic_cloud.cpp:567-575`、`localization.cpp:494-497` | 按消息时间戳查询+小超时；加载失败 throw |

## 3. RM2027 规则变化 → 代码适配清单

依据《RM2027 规则手册 V1.0.0》逐节核对：

### 3.1 直接影响算法的变更

| 规则变化 | 手册位置 | 对代码的影响 |
|---|---|---|
| **雷达计分改「被标记进度 P」制**：准确 d<0.8m、半准确 0.8~1.6m；**每 0.5s 无数据记一次「错误」**；判定频率=发送频率 | 5.7.4 (p113) | ① 裁判发送循环必须**恒频、独立于视觉处理节拍**（建议 ≥5Hz，用卡尔曼 `predict_future` 外推补洞）；② 位置精度要求量化为 0.8m（当前 σ=0.2m 余量充足）；③ 断流比错发更亏——`referee` 通信要加看门狗 |

## 5. 可读性重构路线（长期，最重要的工程）

现状三座大山：`main_event_loop.py`（~2400 行）、`interface/core.py`（~6000 行）、
`tracker.py`（千行级状态机）。**拆解的前提是行为不变，靠的是已有的
`tests/` + 回放验证，每一步一个提交。**

### 5.1 立规矩（新人贡献前读）

1. **死代码即删**：不留「注释掉的实现」，git 历史就是存档（本分支已示范）。
2. **单位写进名字**：`*_threshold_m`、`*_age_sec`——本次 m²/m 的坑就是教训。
3. **魔法数进配置**：tracker 里 1.5/2.0/2.5 这类门限，新加的一律带 yaml 键。
4. **文件长度上限 ~800 行**：超过就按职责拆模块（拆比不拆好，早拆比晚拆好）。
5. **热路径注释写「为什么」**：如 `pipeline.py::publish_latest` 的取舍注释是全仓库范本。

### 5.2 拆解第一步（建议顺序）

1. `main_event_loop.py`：把「模块计时表 + 指标导出」（约 400 行纯文案/统计）拆成
   `pipeline_metrics.py`；再把 A/B 流水线线程拆成 `stage_a.py`/`stage_b.py`。
   拆完 `main_event_loop` 只剩装配与事件分发，预计 <800 行。
2. `interface/core.py`：先拆出 `KeypointCalibrationDialog`（标定对话框）与
   场地渲染，UI 只留布局与信号槽。
3. `tracker.py`：`process_observations` 的十段已有分段计时命名，天然是目录——
   每两三个阶段抽一个私有模块，`type.py` 的数据结构注释同步。

### 5.3 配套学习材料

`learning/basics/`（路线 0）已就位；本篇之后，新人的完整路径是：
basics → 导读 01~12 → 本篇 → 挑第 4/5 节里的一项动手。
