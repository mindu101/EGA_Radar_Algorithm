## 本次修复

1. 补齐 Livox 的 `pcd_HAP_launch.py`：从已安装驱动的 `msg_HAP_launch.py` 生成，设置 `xfer_format=0`，发布标准 `PointCloud2`。源码目录和安装目录均保存了一份，重新编译后仍可安装。
2. 修正 `Main_ws/interface/core.py` 的 Qt 插件路径：使用 `QLibraryInfo.PluginsPath` 找到 pip 安装的 PyQt5 插件。原来的 `$CONDA_PREFIX/plugins` 不存在，会使 xcb 初始化失败。
3. 回放启动器支持 `CONDA_ENV`，与 `start_fusion.sh` 保持一致，默认仍为 `cud128`。
4. 原始引擎反序列化报版本不匹配。使用 TensorRT 10 的 FP16 构建方式，依据仓库提供的 ONNX 在本机重新构建引擎。原始模型保留，本机引擎放在 `Main_ws/weights/local/`。
5. `Main_ws/config/params.yaml` 已指向这两个本机引擎。不要直接换回仓库原始 `.engine`，其 TensorRT 序列化版本与当前环境不匹配。
6. 修复当前 Ultralytics 与车辆检测耗时统计包装的兼容问题：`track()` 每次刷新回调，原包装丢失了回调身份，导致重复调用 BoT-SORT，新目标无法确认。现在在每批预测开始时安装统计包装，并保留回调身份；新增回归测试验证每帧只更新跟踪器一次。
7. 补装 ONNX 构建依赖及 `lap==0.5.13`；数字分类器所需的 MobileNet 初始化权重已缓存。
8. 修复高 DPI 下主界面超出屏幕：三栏可拖动调宽，右侧状态与控制面板可滚动，相机控制和前哨站预览/参数分为标签页，投影选项分行排列。取消图像区域的固定大尺寸，保留图像比例；手动外参与关键点标定弹窗也支持缩放和滚动。

本机使用的是 TensorRT 10 的 CUDA 13 包，Python 导入名仍为 `tensorrt`。不要直接执行不带版本的 `pip install -U tensorrt`。下载并校验过 SHA256 的运行库与绑定 wheel 保存在 `logs/deployment/wheels/`；如果更换 GPU 或 TensorRT 版本，应重新构建本机引擎。

## 使用方法

无需先手动激活 conda，直接在仓库根目录执行：

```bash
# 检查回放数据路径和时间范围
./run_replay_test.sh Main_ws/config/test.yaml --preflight-only

# 启动相机录像与点云回放
./run_replay_test.sh Main_ws/config/test.yaml
```

界面出现后点击“直接输入外参”，在弹窗中点击“导入最近外参”并确认，再点击“启动雷达站”。回放启动器会将该次录像的外参文件传给界面。样例结束后界面保留，关闭窗口或按 Ctrl+C 退出。

接真实硬件时：

```bash
./start_fusion.sh
# 不启动 RViz 时
LAUNCH_RVIZ=false ./start_fusion.sh
```

实机采集仍需相机标定及雷达网络配置。当前 Livox HAP 配置中的主机 IP 为 `192.168.1.5`、雷达 IP 为 `192.168.1.100`；接入实际设备前需按设备参数确认。本次部署不更改系统网卡地址。

## MID360 点云不可见排查（2026-10-23）

运行 `./start_mid360_ca016.sh` 时，发现两份上次退出后遗留的 MID360 驱动同时占用主机 UDP 端口，且 `/livox/lidar` 没有发布者。停止这两份孤立驱动后，单驱动重新连接雷达并恢复发布。`start_fusion.sh` 现在在启动新驱动前检查“进程仍在但没有点云发布者”的故障状态，等待收到非空 `PointCloud2` 后才启动主界面，并在复用已有雷达时也打开 RViz。启动的 ROS 进程使用独立会话，退出时由启动脚本统一发送中断信号，避免重复启动和遗留进程。

实机复测：`/livox/lidar` 约 10 Hz、每帧约 19,968～20,064 点；RViz 订阅 `/livox/lidar` 并能看到室内原始点云，CA016 重新连接并开始采集。点云是单独 RViz 窗口中的实时视图，主界面不会生成点云图片；若主界面遮住 RViz，按 Alt+Tab 切换。当前室内台架仍不应期待场地聚类或有效空间融合。
